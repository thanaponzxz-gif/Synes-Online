# Global Plugin & Skills Playbook (ใช้ได้ทุกโปรเจกต์ของเจ้าของ)

> แม่แบบกลางจาก ADR-010 ของ Synes (2026-11-23) ใช้กับ Synes Online, K.N.D. และโปรเจกต์ใหม่ได้โดยไม่ต้องออกแบบกฎใหม่
> โปรเจกต์ใช้ไฟล์นี้ได้ 2 แบบ: คัดลอกข้อ 6 ไปวางใน CLAUDE.md/AGENTS.md ของโปรเจกต์ แล้วทำตาราง "บทบาท → เครื่องมือ" ของโปรเจกต์เอง (ตัวอย่างของ Synes อยู่ใน `PLUGIN_SKILLS.md`)
> **ข้อห้ามกลาง:** ห้ามเปลี่ยนสถาปัตยกรรม, art direction หรือขอบเขตงานเพียงเพราะมีเครื่องมือใหม่

## 1. วงจรของเครื่องมือหนึ่งตัว
`พบความต้องการจริง` → `ตรวจของเดิม` → `ตรวจแหล่ง/โค้ด/license` → `วัด token` → `ขออนุมัติ` → `เจ้าของติดตั้ง+เชื่อมบัญชี` → `ทดสอบงานจริงขนาดเล็ก` → `พร้อมใช้` หรือ `ไม่ใช้`
| ขั้น | ทำอย่างไร | เครื่องมือ |
|---|---|---|
| ความต้องการจริง | ระบุงานที่ติดหรือทำซ้ำบ่อย ไม่เพิ่มเพราะ "น่าจะดี" | backlog ของโปรเจกต์ |
| ตรวจของเดิม | ดูว่ามี plugin/connector/skill ที่ทำได้แล้วหรือยัง | `ListPlugins`, `ListConnectors`, `ListSkills`, `claude mcp list` |
| ตรวจแหล่ง | ใช้เฉพาะ Anthropic Directory / Knowledge Work catalog หรือ repo ของผู้ผลิต เลือกรุ่นที่ publisher เป็นผู้ผลิตและมี upstream · ถ้ามีทั้ง connector อย่างเดียวและ connector+skills ให้เลือกรุ่นที่ครบกว่า เว้นแต่ token เกินคุ้ม | `SearchPlugins`, `SearchMcpRegistry` |
| ตรวจโค้ด | clone upstream ไว้นอก repo อ่าน `LICENSE`, `.mcp.json` (ปลายทาง), `hooks`, สคริปต์ทุกไฟล์, tool ที่สร้างค่าใช้จ่ายหรือเขียนข้อมูล | `git clone --depth 1` |
| วัด token | `claude --plugin-dir <clone> plugin details <ชื่อ>` → ค่า "Always-on" คือ token ที่จ่ายทุกเซสชัน | Claude Code ≥ 2.1.330 |
| ขออนุมัติ | รวมรายการ: ต้องเชื่อมบัญชีอะไร, สิทธิ์ที่ขอ, ความเสี่ยงค่าใช้จ่าย, token | ไฟล์ setup ของโปรเจกต์ |
| ทดสอบ | งานจริงขนาดเล็ก 1 ชิ้นที่อยู่ในขอบเขตเดิม แบบอ่านอย่างเดียวก่อน เทียบกับวิธีเดิมตามข้อ 3 | ตารางผลทดสอบของโปรเจกต์ |

## 2. ระดับ Global หรือ Project
| สิ่งที่ติดตั้ง | ระดับ | เหตุผล |
|---|---|---|
| plugin/connector ของ claude.ai | Global (ผูกบัญชี) | มีผลทุกโปรเจกต์ จึงเปิดเฉพาะตอนใช้ ปิดเมื่อจบงาน |
| MCP ในเครื่อง (`claude mcp add --scope user`) | Global ในเครื่องนั้น | เช่น Blender MCP ใช้ได้เฉพาะเซสชันบนเครื่องนั้น |
| MCP ที่ทั้งทีมต้องใช้ในโปรเจกต์เดียว | Project (`.mcp.json` ใน repo) | ห้ามใส่ key ลงไฟล์ ใช้ secret ของ environment |
| skill เฉพาะโปรเจกต์ | Project (`.claude/skills/`) | โหลดเฉพาะ repo นั้น |

## 3. ทดสอบงานจริงขนาดเล็ก: ตัวชี้วัดกลาง
ทุกเครื่องมือทดสอบด้วยงานเดียวกัน 2 วิธี (วิธีเดิม vs เครื่องมือใหม่) แล้วบันทึกแถวละวิธี
| ตัวชี้วัด | วัดอย่างไร |
|---|---|
| Quality | เกณฑ์ผ่าน/ไม่ผ่านที่เขียนไว้ก่อนทดสอบ (เช่น ขอบ alpha ไม่มีจุดรบกวน, ค่าสีตรง ±1) + ผู้ตรวจอิสระ (QA หรือทีมอื่น) |
| Time | เวลาจริงตั้งแต่เริ่มจนได้ผลที่ผ่านเกณฑ์ |
| Token | `get_session` → `context_usage` ก่อน/หลัง หรือ `/cost` ในเครื่อง · แยก token เปิดค้างของ plugin (ข้อ 1) ออกจาก token ตอนใช้ |
| เงิน | ต้องเป็น 0 ในรอบทดสอบ ถ้า tool จะสร้างค่าใช้จ่ายให้หยุดก่อน |
| ความปลอดภัย | สิทธิ์ที่ให้จริง, ไฟล์ที่ถูกเขียน, ข้อมูลที่ออกนอกเครื่อง |
ผลสรุป: `พร้อมใช้` เมื่อผ่าน Quality และไม่แย่กว่าวิธีเดิมทั้ง Time และ Token รวม หรือแย่กว่าแต่เจ้าของยอมรับเพราะคุณภาพดีขึ้น · ห้ามเขียน "พร้อมใช้" ถ้ายังไม่ได้เรียก tool จริงสำเร็จ

## 4. บทบาท → ประเภทเครื่องมือ (แม่แบบ)
| บทบาท | ประเภทเครื่องมือ | ตัวอย่าง |
|---|---|---|
| PM | จัดสรร/เปิดปิดเครื่องมือ, คุมต้นทุน | `ListPlugins`, ตารางของโปรเจกต์ |
| Art Director | ไฟล์ดีไซน์, ภาพ, 3D | Figma, Adobe, Blender |
| UI/UX Designer | ไฟล์ดีไซน์, คลังอ้างอิง | Figma, Mobbin |
| Technical Artist | 3D, แก้ภาพ | Blender MCP, Adobe |
| Marketing | สื่อโปรโมต | Canva, Adobe |
| Backend Engineer | DB/Auth | Supabase (หลังมี ADR) |
| QA | ทดสอบ/ตรวจอิสระ | Playwright, screenshot ของเครื่องมือออกแบบ |
ถ้าโปรเจกต์มีกฎแบ่งทีม (เช่น Synes ADR-007 ให้ทีม A ออกแบบ) ให้กฎนั้นชนะ บทบาทในตารางเป็น "หมวกงาน" ไม่ต้องเปิด agent แยกทุกบทบาท

## 5. ข้อห้ามกลาง
- ห้ามติดตั้ง, เชื่อมบัญชี, สมัคร หรือจ่ายเงินแทนเจ้าของ · ห้ามซื้อ stock asset/license ผ่าน tool
- ห้ามเปิดทุก plugin ค้างไว้ (6 ตัวรวม ~11k token ต่อเซสชัน)
- ห้ามเปิดพอร์ตของ MCP ในเครื่องสู่ภายนอก, ห้ามเปิด telemetry ที่ส่งเนื้อหางาน
- ห้ามเก็บภาพอ้างอิงที่มีลิขสิทธิ์ของผู้อื่นใน repo สาธารณะ
- ห้ามใช้เครื่องมือเป็นเหตุให้เปลี่ยนสถาปัตยกรรม, art direction หรือเพิ่มขอบเขต

## 6. ข้อความสั้นสำหรับวางใน CLAUDE.md / AGENTS.md ของโปรเจกต์อื่น
```
## Plugin & Skills Management (Global Playbook ของเจ้าของ)
- ก่อนเริ่มงาน เลือกเครื่องมือเฉพาะทางที่เหมาะที่สุดจากตาราง "บทบาท → เครื่องมือ" ของโปรเจกต์ (<ไฟล์ของโปรเจกต์>) อย่าเขียนโค้ดทดแทนโดยไม่จำเป็น
- เปิดเฉพาะ plugin ที่งานนั้นใช้ ปิดเมื่อจบงาน
- ติดตั้ง/เชื่อมบัญชี/เสียเงิน ต้องให้เจ้าของทำหรืออนุมัติ · ใช้แหล่งทางการ ตรวจโค้ดและ license ก่อน
- ไม่ได้ทดสอบจริง = ไม่รายงานว่าพร้อมใช้ · ทดสอบด้วยงานจริงขนาดเล็ก เทียบ Quality/Time/Token
- เครื่องมือใหม่ไม่เปลี่ยนสถาปัตยกรรม, art direction หรือขอบเขตงาน
```
