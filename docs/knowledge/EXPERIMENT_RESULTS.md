## ทดลองแล้ว (สรุปจากหลักฐานใน repo)

### EXP-001: เอนจิน Three.js เทียบ PlayCanvas · 2026-11-19 · DONE-ADOPT
- ฉากเดียวกันทั้งสองเอนจิน (`spike/`, `docs/spike-results.md`)
- Three.js ขนาดเล็กกว่า 2.2 เท่า (132 KB เทียบ 296 KB gzip), เฟรมแรกเร็วกว่า ~0.8 s บนโปรไฟล์ Android ระดับล่าง + Slow 4G, FPS สูงกว่า 1.25–2 เท่า (GPU ซอฟต์แวร์), heap ต่ำกว่า ~40%
- **ยังไม่ได้ทดสอบบนเครื่องจริง** → ADR-001 รับรองชั่วคราว
- บทเรียน: วัดด้วยฉากเดียวกันก่อนเลือกเครื่องมือหลัก

### EXP-002: โมเดลจากสคริปต์ Blender headless แทน asset ภายนอก · 2026-11-19 · DONE-ADOPT
- `tools/blender/build_kit.py` → `synes_kit.glb` 30 asset, 15,232 tris, 537.6 KB, build ซ้ำได้ไฟล์เดิมทุกไบต์, `verify_kit.py` ผ่าน 293 ข้อ
- ข้อดี: สิทธิ์ของโปรเจค 100%, ไม่มีค่าใช้จ่าย, ตรวจซ้ำอัตโนมัติได้ · ข้อเสีย: ตัวละครแยกชิ้นทำให้ draw calls สูง (~81 ในรอบ 1)
- → ADR-003, มติ ข-2

### EXP-003: GPT Image → สคริปต์ตัดภาพ → เกม (HUD skin v01, DES-002) · 2026-11-20 · รอทีม A ตรวจ
- ภาพต้นแบบ 1 แผ่น (RGBA 1774×887) → `tools/art/slice_hud.py` ตัด 8 ชิ้น (คัดลอกพิกเซลตรง ไม่วาดเพิ่ม ลบจุดรบกวน alpha < 8)
- งบ: JS เท่าเดิม (770,879 B), CSS 11.65 → 13.5 KB, PNG ใน build 536 KB
- QA: test 62/62, typecheck ผ่าน, lifecycle 20/20 (server จริง) · **Android/iPhone ยังไม่ได้ทดสอบ**
- ปัญหาที่พบ: ไม่มี prompt ฉบับเต็ม (L-010), ภาพมีจุดรบกวน alpha 1–15 ทั่วแผ่น (L-011), เพชรบนกรอบชิดขอบภาพ, คำถามถึงทีม A Q35–Q49 ใน `docs/design/DES-002-teamB.md`
- **ข้อสรุปเบื้องต้น:** เส้นทาง "AI สร้างภาพ → สคริปต์ตัด → เกม" ใช้ได้กับ UI และใช้ token น้อยเพราะงานซ้ำทำด้วยสคริปต์ ต้องรอทีม A และเจ้าของตัดสินคุณภาพ
- เวลาเจ้าของ/รอบแก้ของ GPT: **ไม่ได้วัด**

### EXP-004: ให้บอทตัดสินคูลดาวน์หลบ 17 กับ 26 tick · 2026-11-20 · DONE (บอทตัดสินไม่ได้)
- `tools/qa/dodge-cd-compare.ts`, `docs/qa/dodge-cd-compare.md`, `docs/qa/dodge-cd-sameseed.md`
- บอทชนะ 100% ทั้งสองค่า ท่าบอสที่ทับตัวผู้เล่นห่างกัน ≥ 1.97 s จึงแยกไม่ออก · agent 2 คนเทียบกันตรง ๆ ไม่ได้ · replay ชี้ว่าที่โดนเพราะหลบเร็วไป ไม่ใช่ติดคูลดาวน์
- → L-007: เรื่อง "ความรู้สึก" ต้องให้คนเล่นจริงตัดสิน บอทใช้ตรวจความถูกต้อง

### EXP-005: เพลย์เทสต์ด้วย agent ที่ไม่รู้กลไกเกม (Sonnet) · 2026-11-20 · DONE-ADOPT

## เสนอไว้ (ยังไม่ได้ทำ เรียงตามความคุ้มที่คาด)

### EXP-101: ลด token ที่โหลดทุกเซสชัน · PLANNED · ต้องอนุมัติ: เจ้าของ (แก้กฎเหล็กใน CLAUDE.md)
- **ปัญหา:** CLAUDE.md (16.5 KB) + `docs/PROJECT_SYNES.md` (21.6 KB) (วัด 2026-11-21) ถูกโหลดทุกเซสชันและทุก subagent ที่ไม่ใช่ Explore/Plan โดยเฉพาะบันทึกเซสชัน (ข้อ 7) และรายละเอียด rollover (ข้อ 5–5.1) ที่ใช้แค่ตอนจบรอบ
- **วิธีใหม่:** ย้ายขั้นตอน rollover ไป skill `synes-pm` (มีอยู่แล้วบางส่วน) และย้ายบันทึกเซสชันเก่าไป `docs/HANDOFF.md` โดยไม่ตัดกฎข้อใด
- **วัด:** `/context` บนเครื่องเจ้าของ หรือ `context_usage` ของเซสชันใหม่ ก่อน/หลัง
- คาดว่าคุ้มที่สุด เพราะไม่มีค่าใช้จ่ายและลดทุกคำขอ แต่ยังไม่ได้วัด

### EXP-102: ภาพ → 3D นำร่อง 1 ชิ้น เทียบกับสคริปต์ Blender · PLANNED · ต้องอนุมัติ: บรีฟทีม A + เจ้าของ (บัญชี Tripo แบบเสียเงิน หรือ GPU สำหรับ Hunyuan3D)
- ชิ้นที่เสนอ: พร็อพหรือศัตรู 1 ชิ้นที่ทีม A เลือก (ไม่ใช่ตัวละครหลัก)
- **วัด:** tris/draw calls/KB เทียบชิ้นเดิมใน `synes_kit.glb`, เวลาที่ต้องเก็บงานใน Blender, จำนวนรอบที่ต้องสร้างใหม่, ค่าใช้จ่ายต่อชิ้น, ภาพเทียบในเกม
- เกณฑ์ผ่าน: ทีม A และเจ้าของเห็นว่าสวยขึ้นชัด และอยู่ในงบมือถือหลังลด polygon

### EXP-103: บีบอัดโมเดลด้วย meshopt · PLANNED · ต้องอนุมัติ: ติดตั้ง npm package (หลังตรวจ license)

### EXP-104: ตัวละคร skinned mesh ชิ้นเดียวเพื่อลด draw calls · PLANNED · ต้องอนุมัติ: ทีม A ถ้าท่าทางเปลี่ยน
