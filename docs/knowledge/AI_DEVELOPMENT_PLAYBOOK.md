# AI Development Playbook: Synes Online

> ที่มา: คำสั่งเจ้าของ "AI Continuous Learning & Workflow Optimization" (2026-11-21, ADR-008)
> ไฟล์นี้บอกว่าทีมทำงานกับ AI และเครื่องมืออย่างไร ส่วนรายชื่อเครื่องมือดูที่ `TOOL_REGISTRY.md`, ผลทดลองดูที่ `EXPERIMENT_RESULTS.md` และบทเรียนดูที่ `LESSONS_LEARNED.md`
> **อ่านเฉพาะหัวข้อที่เกี่ยวกับงานรอบนั้น** ไฟล์ในโฟลเดอร์นี้ไม่ถูก `@import` เข้า CLAUDE.md โดยตั้งใจ เพื่อไม่ให้ทุกเซสชันเสีย token อ่านทั้งหมด

## 0. ขอบเขตและลำดับความสำคัญของกฎ
คำสั่งนี้**เพิ่ม**วิธีเรียนรู้ ไม่ได้แทนกฎเดิม ถ้าขัดกัน ให้ใช้ลำดับนี้
1. CLAUDE.md ข้อ 0 (ADR-007): ทีม A (GPT Codex) ออกแบบก่อน ทีม B (Claude) ลงมือ
2. CLAUDE.md ข้อ 6: สิ่งที่ต้องให้เจ้าของยืนยันก่อน (เงิน, บัญชีภายนอก, ติดตั้ง, เปิดสาธารณะ, ใช้ asset จริง)
3. ADR-001 + มติ ข-1: **Synes ใช้ Three.js ไม่ใช่ Godot** ทุก pipeline ในคำสั่งที่จบที่ "Godot" ให้อ่านเป็น "Three.js (GLTFLoader)"
4. `docs/PROJECT_SYNES.md` ข้อ 1: สิ่งที่ห้ามเปลี่ยน (ต้นฉบับ, แยกจาก TERRAVIA, server ตัดสินผล, ห้ามสร้าง MMORPG ล่วงหน้า)
5. Playbook นี้

ข้อจำกัดจากคำสั่งเจ้าของ: ห้ามหลุด roadmap · ห้ามเปลี่ยนเอนจิน/สถาปัตยกรรมเพราะเจอเทคนิคใหม่ · ห้ามสมัคร/จ่ายเงิน/ติดตั้ง/เผยแพร่โดยไม่ได้รับอนุญาต · ห้ามนำผลทดลองที่ยังไม่ผ่าน QA เข้า `main` · ไม่ต้องใช้ทุกเทคนิค

### 1.1 ตัวชี้วัดมาตรฐาน (ใช้ทุกการทดลอง)
- **คุณภาพ:** ผ่านเกณฑ์ตรวจกี่ข้อ, ภาพเทียบในเกม, คะแนนเพลย์เทสต์ (ความชัด/สนุก/ภาพ) ถ้าเกี่ยว
- **งบเกม (มือถือ):** draw calls, triangles, ขนาดดาวน์โหลด, เวลาเฟรมแรก เทียบกับ `docs/qa/baseline-2b.md` (ลานบอส draw calls 89/95/170 ที่ low/medium/high, เป้า < 40)
- **เวลา:** เวลาคน (เจ้าของ) และเวลาเครื่อง แยกกัน
- **เงิน:** ค่าบริการจริงต่อชิ้น/ต่อเดือน
- **token:** วัดจาก `/usage` (ส่วน attribution) หรือ `/context` บนเครื่องเจ้าของ, หรือ `context_usage` ของเซสชันคลาวด์ ถ้าวัดไม่ได้ให้เขียน "ไม่ได้วัด" ห้ามเดา

### 3.2 ข้อเท็จจริงเรื่อง token (ตรวจจากเอกสาร Claude Code, 2026-11-21)
- **การแยกงานขนานไม่ได้ลด token รวม** subagent ช่วยให้บริบทหลักสะอาดเพราะผลยาว ๆ อยู่ใน context ของมันเอง แต่คำขอของ subagent ยังกินโควตาเหมือนเดิม ประโยชน์จริงคือเร็วขึ้นและบริบทไม่ปนกัน (ตรงกับ PROJECT_SYNES ข้อ 1)
- **Agent teams** (ฟีเจอร์ทดลอง ปิดไว้เป็นค่าเริ่มต้น) ใช้ token ราว 7 เท่าของเซสชันปกติเมื่อ teammate อยู่ใน plan mode → **ไม่ใช้** ใน Synes
- CLAUDE.md ถูกโหลดทุกครั้งที่เริ่มเซสชัน เอกสารแนะนำให้เก็บไว้ < 200 บรรทัดและย้ายขั้นตอนเฉพาะงานไปเป็น skill (โหลดเมื่อใช้เท่านั้น)
  ณ 2026-11-21 (หลังเพิ่มข้อ 7) CLAUDE.md 102 บรรทัด / 16.5 KB + `docs/PROJECT_SYNES.md` 98 บรรทัด / 21.6 KB ถูกโหลดทุกเซสชัน (ภาษาไทยกิน token ต่อตัวอักษรมากกว่าอังกฤษ) → ทดลองลดใน EXP-101
- Sonnet ทำงานโค้ดส่วนใหญ่ได้ดีและถูกกว่า Opus · ถ้าเซสชันหลักเป็น Opus, subagent ที่ไม่ได้ระบุ model จะใช้ Opus ตาม
- CLI (`gh`, `git`, `node tools/...`) ประหยัดบริบทกว่า MCP server · ปิด MCP server ที่ไม่ได้ใช้
- `/clear` เมื่อเปลี่ยนไปงานที่ไม่เกี่ยวกัน (ไม่เสีย token) ส่วน `/compact` ต้องอ่านบทสนทนาทั้งหมดเพื่อสรุป จึงเป็นคำขอใหญ่
- hook กรองผลลัพธ์ยาวก่อนเข้าบริบทได้ เช่น ให้ `npm test` ส่งกลับเฉพาะบรรทัดที่ fail

### 3.3 กฎปฏิบัติ
1. **สคริปต์ก่อน AI:** งานที่ได้คำตอบเดิมทุกครั้งให้เขียนสคริปต์ครั้งเดียวแล้วรันซ้ำ ตัวอย่างที่มีแล้ว `tools/art/slice_hud.py`, `tools/qa/baseline.mjs`, `tools/qa/clip.mjs`, `tools/qa/dodge-cd-compare.ts`, `tools/blender/verify_kit.py`
2. **อ่านให้น้อยที่สุดที่พอ:** ใช้ `grep`/`sed -n` อ่านเฉพาะช่วง ห้าม `cat` ไฟล์ log หรือ JSON ใหญ่ทั้งไฟล์
3. **แยกสายเมื่อไฟล์ไม่ทับกันจริงเท่านั้น** (≤ 3 สาย ตาม `docs/OWNERSHIP.md`) บรีฟสายต้องสั้นและระบุไฟล์ที่แก้ได้ เพราะทุกอย่างในบรีฟกิน context ของสายนั้นตั้งแต่ต้น
4. Explore subagent: ตั้งแต่ Claude Code v2.1.198 ใช้โมเดลเดียวกับเซสชันหลัก (เดิมใช้ Haiku) ถ้าต้องการค้นด้วยโมเดลถูก ให้สร้าง subagent ชื่อ `Explore` ของโปรเจคที่ตั้ง `model: haiku` (ยังไม่ได้ทำ ดู EXP-105)
5. ใช้ skill แทนการอธิบายซ้ำ: งานที่ทำซ้ำ ≥ 2 รอบให้ทำเป็น skill ใน `.claude/skills/` (CLAUDE.md ข้อ 3)
6. ก่อนจบรอบ ให้เขียนบทเรียนใหม่ (ถ้ามี) ลง `LESSONS_LEARNED.md` 1–3 บรรทัด ไม่ต้องเขียนถ้าไม่มีอะไรใหม่

## 4. Pipeline asset (ข้อเสนอให้ทดลอง ยังไม่ใช้จริง)
คำสั่งเจ้าของ: ภาพต้นแบบ → 3D → Blender → Rig → Animation → GLB → ~~Godot~~ **Three.js**
ด่านอนุมัติเดิม (ADR-006/007) ยังอยู่ครบ: บรีฟของทีม A → `assets/_inbox/` → ทีม B ตรวจ → ภาพเทียบในเกม → เจ้าของ APPROVED

| ขั้น | เครื่องมือที่เป็นตัวเลือก | ใครทำ | ด่านตรวจ |
|---|---|---|---|
| 1 ภาพต้นแบบ (หน้า/ข้าง/หลัง, T-pose ถ้าเป็นตัวละคร) | GPT Image (ใช้อยู่), Gemini (ตัวเลือกสำรอง) | ทีม A เขียนบรีฟ, เจ้าของสั่งผลิต | ห้ามใช้ส้ม #FF7A1A / แดง #FF3355, ต้นฉบับ |
| 2 ภาพ → โมเดล 3D | Tripo (ต้องสมัครแบบเสียเงิน), Hunyuan3D (รันเอง ต้องมี GPU) | เจ้าของรัน หรือทีม B ถ้ามีบัญชี/เครื่องที่อนุมัติ | license ตาม `TOOL_REGISTRY.md` |
| 3 เก็บงานใน Blender: ลด polygon, จุดหมุน, ขนาดจริง, สีวัสดุตาม palette | Blender headless (`bpy`) ด้วยสคริปต์ในโฟลเดอร์ `tools/blender/` | ทีม B (Sonnet) | งบ tris/draw calls ตามข้อ 1.1 |
| 4 Rig | Blender (Rigify/armature จากสคริปต์), Mixamo (humanoid เท่านั้น), auto-rig ของ Tripo | ทีม B | ตัวละครสัดส่วนเพี้ยนมากอาจ rig อัตโนมัติไม่ได้ |
| 5 Animation | คีย์เฟรมจากสคริปต์, Mixamo | ทีม B ทำ, ทีม A ตัดสินความรู้สึกของท่า | ท่าที่ผู้เล่นเห็นต้องผ่านทีม A |
| 6 Export | `.glb` ชื่อ `ประเภท_ชื่อ_vNN` | ทีม B | `verify_kit.py` หรือสคริปต์ตรวจแบบเดียวกัน |
| 7 บีบอัด | meshopt ผ่าน gltf-transform (ต้องขออนุมัติติดตั้ง) | ทีม B | ขนาดก่อน/หลัง |
| 8 เข้าเกม | `GLTFLoader` ใน `src/render/models.ts` | ทีม B | ภาพเทียบในเกม → เจ้าของ |

ข้อสังเกตทางเทคนิคที่ต้องทดสอบก่อนเชื่อ:
- โมเดลจาก AI มักมี polygon และ texture มากเกินงบมือถือ ตอนนี้ชุด `synes_kit.glb` ทั้งชุดมี 15,232 tris และใช้สีจาก material เกือบทั้งหมด (texture ในฉากมีแค่ 2 อัน)
- ตัวละครตอนนี้แยกชิ้นเพื่อขยับ ทำให้ draw calls สูง การทำ skinned mesh ชิ้นเดียวอาจลด draw calls ได้ ต้องวัดจริง (EXP-104)
- Synes ต้องเป็นงานต้นฉบับ (PROJECT_SYNES ข้อ 1) asset สำเร็จรูปจึง**ยังใช้ในเกมไม่ได้**จนกว่าเจ้าของตัดสิน (ดู `TOOL_REGISTRY.md` หมวด asset pack)

- ข้ามอุปกรณ์: เซสชันคลาวด์ทำงานต่อได้จากทุกเครื่องเพราะ push ทุกรอบ · เครื่อง Windows ของเจ้าของใช้ `tools/setup/setup-windows.ps1` (Remote Control) · iPhone ทดสอบผ่าน GitHub Pages (ต้องถามก่อนอัปเดตทุกครั้ง)
- ข้อจำกัดที่รู้แล้ว: container คลาวด์ไม่มี GPU และเปิด `github.io` / หน้า claude.ai ที่ต้องล็อกอินไม่ได้ จึงตรวจหน้าเว็บที่โฮสต์แล้วเองไม่ได้

## 6. ด่านความปลอดภัยและลิขสิทธิ์ (ตรวจก่อนใช้เครื่องมือหรือ asset ภายนอกทุกครั้ง)
1. อ่านเงื่อนไขการใช้งานจากหน้าทางการ (ToS/License/Help) ของแผนที่จะใช้จริง และใส่วันที่ตรวจ
2. สิทธิ์ผลงาน: ใครเป็นเจ้าของ output, ใช้เชิงพาณิชย์ได้ไหม, ต้องใส่เครดิตไหม, **มีข้อห้ามด้านพื้นที่ไหม** (เกมบนเว็บเปิดได้ทั่วโลก)
3. การแจกจ่าย: repo เป็น Public การ commit ไฟล์ดิบเท่ากับแจกจ่าย บางเงื่อนไขห้ามแจกไฟล์ดิบ (เช่น Mixamo)
4. โค้ดภายนอก (plugin, add-on, MCP server): อ่านโค้ดก่อนติดตั้ง และระวังตัวที่รันโค้ดใดก็ได้ (เช่น add-on ของ blender-mcp รัน Python ตามคำสั่งผ่าน socket)
5. บันทึกที่มา (เครื่องมือ, prompt ฉบับเต็ม, แผน/บัญชี, license, วันที่) ใน `docs/ASSETS.md` **ตอนสร้าง** ไม่ใช่ย้อนหลัง
6. key/token ของบริการภายนอกห้ามอยู่ใน repo หรือในบรีฟ
7. เรื่องกฎหมายที่ไม่ชัด ให้สรุปข้อเท็จจริงให้เจ้าของตัดสิน ทีมไม่ใช่ทนาย

## 7. Infrastructure (ศึกษาไว้ก่อน ยังไม่เช่า ตามคำสั่งเจ้าของ)
- **ยังไม่ต้องใช้:** ลิงก์ทดลองเล่นตอนนี้เป็น static (Artifact/GitHub Pages, โหมดออฟไลน์) server จำเป็นเมื่อถึง backlog ข้อ 7 (เลเวล/อุปกรณ์ที่ server บันทึก, co-op 2–4 คน)
- **สิ่งที่ server ต้องรองรับ (จากสถาปัตยกรรมปัจจุบัน):** Node.js (`server/index.ts`), จำลอง sim 30 Hz ซ้ำจาก input log ตอนจบด่าน (ADR-002), ต่อไปคือ WebSocket real-time สำหรับ co-op, ฐานข้อมูล guest id → ความคืบหน้า, HTTPS
- **ทางเลือกที่จะเทียบเมื่อถึงเวลา:** static CDN + VPS ขนาดเล็กสำหรับ `/api` (ถูกที่สุด เริ่มได้เร็ว) · PaaS ที่รัน Node (ตั้งค่าน้อย แต่บางเจ้าจำกัด WebSocket/เวลารัน) · Dedicated server (เฉพาะเมื่อมีผู้เล่นพร้อมกันจำนวนมาก ไม่ใช่ตอนนี้)
- **เกณฑ์เทียบ:** ค่าใช้จ่ายต่อเดือน, latency จากไทย, รองรับ WebSocket, backup, ความง่ายในการ deploy จาก GitHub, ข้อกำหนดบัญชี/บัตร
- **ยังไม่ได้ตรวจราคาจริง** ราคาเปลี่ยนบ่อย ให้ตรวจจากหน้าทางการตอนจะตัดสินใจ และต้องให้เจ้าของอนุมัติก่อนสมัคร (CLAUDE.md ข้อ 6)
