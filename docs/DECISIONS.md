# Synes Online: บันทึกการตัดสินใจ (ADR)

## ADR-001: เอนจิน render = Three.js (r187) · 2026-11-19 · สถานะ: รับรองชั่วคราว รอผลบนเครื่องจริง
**บริบท:** โจทย์ให้พิจารณา PlayCanvas ก่อน จึงทำ spike ฉากเดียวกันทั้งสองเอนจิน (ดู `docs/spike-results.md`)
**ผลที่วัดได้:** Three.js เล็กกว่า 2.2× (132 KB เทียบ 296 KB gzip), เฟรมแรกบนโปรไฟล์ Android ระดับล่าง + Slow 4G เร็วกว่า ~0.8 s,
FPS บน GPU ซอฟต์แวร์สูงกว่า 1.25–2× และ heap ต่ำกว่า ~40%
**ข้อดีของ PlayCanvas ที่ไม่ได้เลือก:** Editor บนเว็บที่ทีมใช้ร่วมกันได้, ระบบ asset/ECS สำเร็จรูป, การรองรับ WebGPU
แต่ข้อดีหลักคือ Editor ซึ่งเป็นบริการคลาวด์ภายนอก และเราต้องการ pipeline ที่อยู่ใน git ได้ทั้งหมด
**เหตุผล:** การเล่นจากลิงก์บนมือถือให้น้ำหนักกับขนาดดาวน์โหลดและเวลาเข้าถึงการเล่นมากที่สุด ส่วน ecosystem ของ Three.js
(GLTFLoader, ตัวอย่าง, ไลบรารี) ช่วยให้พัฒนาต่อได้ง่าย
**ลดความเสี่ยง:** ตรรกะเกม (`shared/`), input และ UI ไม่ import เอนจิน เอนจินอยู่เฉพาะใน `src/render/`
หากผลบนเครื่องจริงกลับด้าน ให้เปลี่ยนเฉพาะชั้นนี้
**ต้องทำต่อ:** เปิด `/spike/playcanvas/` กับ `/spike/three/` บน Android และ iPhone จริง แล้วจดค่า FPS ลงไฟล์นี้

## ADR-002: กฎที่ server ตัดสินผ่าน deterministic simulation + input replay · 2026-11-19
- `shared/sim/` เป็น simulation แบบ fixed tick 30 Hz ไม่มีการ import เอนจิน DOM หรือ `Math.random`
  และใช้เฉพาะ `+ - * /` กับ `Math.sqrt` (IEEE กำหนดให้ปัดผลตรงกันทุกเครื่อง) โดยไม่ใช้ sin/cos/atan2 ใน sim
  เพราะผลของฟังก์ชันเหล่านี้อาจต่างกันระหว่าง V8 กับ JavaScriptCore
- input ถูก quantize เป็นจำนวนเต็ม (แกน −64..64 + bitmask ปุ่ม) และบันทึกแบบ run-length
- ตอนจบด่าน client ส่ง `{runId, inputLog}` เท่านั้น จากนั้น **server จำลองซ้ำเอง** แล้วตัดสินผลแพ้ชนะ เวลา และความเสียหาย
  และสุ่มรางวัลด้วย secret ของ server client ส่งตัวเลขผลต่อสู้หรือรางวัลเองไม่ได้
- server ตรวจด้วยว่าเวลาจริงระหว่าง `/run/start` ถึง `/run/finish` ไม่น้อยกว่าเวลาในเกม (กัน log ที่สร้างเร็วกว่าเวลาจริง)
- เมื่อทำโหมดหลายผู้เล่น ให้ใช้ sim ตัวเดิมรันบน server แบบ real-time (client ส่ง input แล้ว server ส่ง snapshot กลับ)
- โหมด static (ลิงก์ทดลองเล่นที่ไม่มี server) จะแสดงว่า **"ออฟไลน์: ผลไม่ถูกบันทึก"** และไม่แจกรางวัล

## ADR-003: Asset · 2026-11-19
- ใช้โมเดล low-poly ที่ทีมสร้างเองด้วยสคริปต์ Blender (`tools/blender/`) ใช้สีจาก material ไม่ใช้ texture จึงไฟล์เล็กและเป็นสิทธิ์ของโปรเจกต์ 100%
- มี procedural fallback ในโค้ด ถ้า GLB โหลดไม่สำเร็จ เกมยังเล่นได้
- เสียงทั้งหมดสังเคราะห์ด้วย WebAudio ในโค้ด (ไม่มีไฟล์เสียงจากภายนอก)
- asset ภายนอกทุกชิ้นต้องลงทะเบียนใน `docs/ASSETS.md` ก่อน merge

## ADR-004: การโฮสต์ลิงก์ทดลองเล่น · 2026-11-19
- container นี้ยังไม่มี GitHub remote (บัญชีมองไม่เห็น repo ใด และ GH_TOKEN ใช้ไม่ได้) จึงยังทำ GitHub Pages ไม่ได้
- รอบแรกเผยแพร่ build แบบ static เป็น claude.ai Artifact (เป็นส่วนตัวโดยค่าเริ่มต้น) เพื่อให้เจ้าของเปิดบนมือถือได้
- เป้าหมายระยะยาวคือ static CDN สำหรับ client และ Node server สำหรับ `/api` (`server/`)
