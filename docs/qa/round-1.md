# QA รอบที่ 1 · 2026-11-19 · build slice-1

## สิ่งที่ทดสอบได้จริงในรอบนี้
ทดสอบใน container ด้วย Chromium + Playwright จำลองอุปกรณ์ (GPU เป็น SwiftShader ซึ่งเรนเดอร์ด้วย CPU)

| แพลตฟอร์ม | สถานะ |
|---|---|
| Android จริง | **ยังไม่ได้ทดสอบ** |
| iPhone / Safari (WebKit) จริง | **ยังไม่ได้ทดสอบ** (Chromium ที่ใช้ขนาดจอ iPhone ไม่ใช่ WebKit) |
| เบราว์เซอร์ในแอปแชตจริง (LINE/Facebook/Messenger) | **ยังไม่ได้ทดสอบ** มีแค่การจำลอง UA ของ LINE + ปิด fullscreen API |
| PC (Chromium headless) | ทดสอบแล้ว |

## ผลอัตโนมัติ
- `npm test` ผ่าน 13/13 รายการ ครอบคลุม sim, ความยุติธรรมของเวลาเตือน, การเล่นซ้ำแบบ deterministic, server ไม่เชื่อผลจาก client, กันการส่งผลเร็วกว่าเวลาจริง และกันการส่งซ้ำ
- `node tools/qa/lifecycle.mjs` ผ่าน 20/20 รายการ:
  - สลับแอปแล้ว sim หยุด และเมื่อกลับมาต้องแตะเพื่อเล่นต่อ ไม่โดนตีระหว่างที่ไม่ได้ดูจอ
  - สัญญาณหลุดระหว่างเล่นออนไลน์ เกมยังเล่นต่อได้ และส่งผลให้ server ตรวจได้หลังกลับมาออนไลน์
  - WebGL context หาย มี overlay แจ้ง และเล่นต่อได้หลังกู้คืน
  - UA ของ LINE ที่เรียก fullscreen ไม่ได้ ยังเริ่มเกมได้ จอยสติ๊กสัมผัสเดินได้จริง และปุ่มโจมตีทำงาน
  - layout ที่ 640×360, 760×360, 844×390, 932×430 และ 1280×720 ปุ่มไม่ทับกัน ไม่ทับ HUD ไม่ทับตัวละคร และไม่ล้นจอ
  - ที่ 390×844 (แนวตั้ง) แสดงข้อความให้หมุนจอ และมีปุ่มเลือกเล่นแนวตั้งต่อ

## ปัญหาที่ยังค้าง
- draw calls ~81 แม้รวมชิ้นส่วนพร็อพต่อ material แล้ว ที่เหลือมาจากตัวละคร (แยกชิ้นเพื่อทำแอนิเมชัน) และพร็อพเดี่ยว เป้าหมายต่ำกว่า 40
- ยังไม่มีการวัด FPS/ความร้อน/แบตบนเครื่องจริง ต้องให้เจ้าของเปิดลิงก์ด้วย `?debug=1` แล้วจดค่า
- ความยากปรับจากบอทเท่านั้น (บอทชนะทุก seed และรับดาเมจ 0–72) ต้องให้คนเล่นจริงอย่างน้อย 5 คน แล้วจดเวลาจบ จำนวนครั้งที่แพ้ และท่าที่แพ้
- iOS Safari ไม่รองรับ fullscreen และการล็อกแนวจอ จึงใช้ข้อความให้หมุนจอแทน ต้องตรวจบนเครื่องจริง
