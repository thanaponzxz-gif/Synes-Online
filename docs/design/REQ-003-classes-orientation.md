# REQ-003: อาชีพใหม่ นักเวท + นักธนู (สกิลอลังการ) และการวางแนวจอ แนวตั้ง/แนวนอน
**จาก:** ทีม B (Claude) · **ถึง:** ทีม A (GPT Codex) · **วันที่:** 2026-11-21 · **สถานะ:** REQ เปิด
**อ้างอิง repo:** `main` ที่ `83a18c7` (มีสกิล DES-001, HUD DES-002 และลานปริซึม DES-003/004 ขั้น 1)
ใบนี้มีแค่ความต้องการ ข้อเท็จจริง และข้อจำกัด **ทีม B ไม่ได้ใส่ข้อเสนอดีไซน์** ตามกฎ ADR-007

## 1. ความต้องการของเจ้าของ (ยกมาตรง ๆ 2026-11-21)
> "สร้างตัวละครอีก 2 อาชีพ นักเวท และนักธนู ออกแบบสกิลให้อลังการสวยงาม เพื่อใช้โทเคน และเพิ่มปุ่มเลือกแนวตั้งแนวนอนเล็กๆ (หรือถ้าสามารถทำให้ปรับอัติโนมัติได้ ไม่ได้เพิ่มปุ่ม) ถามทีม"

ทีม B แยกได้ 3 เรื่อง
- **ก.** อาชีพใหม่ 2 อาชีพ: นักเวท (Mage) และนักธนู (Archer)
- **ข.** สกิลของ 2 อาชีพนี้ต้อง "อลังการสวยงาม" แต่คำว่า "เพื่อใช้โทเคน" ยังตีความไม่ได้ (ดู Q50)
- **ค.** การวางแนวจอ: ทำปุ่มเล็กสำหรับเลือกแนวตั้ง/แนวนอน **หรือ** ถ้าทำได้ ให้ปรับอัตโนมัติโดยไม่มีปุ่ม (เจ้าของให้ทีมเลือก)

## 2. ข้อเท็จจริงใน repo ตอนนี้

### 2.1 ตัวละครและการต่อสู้
- มีอาชีพเดียวคือ **นักเดินทาง (Wayfarer)** ใช้ดาบ ทุกค่าอยู่ใน `PLAYER` และ `SKILLS` ใน `shared/data/tuning.ts`
  - HP 120 · ความเร็ว 5.2 m/s · รัศมีตัว 0.42 m
  - โจมตีปกติเป็นคอมโบ 3 จังหวะ ดาเมจ 12/12/22 ระยะ 2.3/2.3/2.6 m ครึ่งมุม ~70° (`arcCos 0.34`) เล็งอัตโนมัติในระยะ 4.2 m
  - หลบ 0.3 s อมตะ 0.3 s คูลดาวน์ 17 tick (หรือ 26 tick ใน variant ทดลอง) หลบเพอร์เฟกต์ทำให้ตีครั้งถัดไป ×1.5 และคืนคูลดาวน์ Chime 2 s
  - ยา 2 ขวด ขวดละ 45 HP
- สกิล 3 ช่อง (DES-001): ระฆังสะท้อน (วงรอบตัว 3.6 m), ฟันเสี้ยวจันทร์ (พัดหน้า 3.0 m ครึ่งมุม 50°), ผลึกพิฆาต (วง 1.5 m ห่างไปข้างหน้า 2.6 m) และอัลติ "มหาระฆัง" ที่ล็อกไว้และยังไม่มีผลใน sim
- **รูปแบบสกิลที่ sim รองรับตอนนี้มี 3 แบบ:** วงรอบตัว, พัดด้านหน้า และวงที่ห่างออกไปข้างหน้า
  ทุกแบบโดน **ครั้งเดียวใน tick เดียว** และล็อกตำแหน่งกับทิศตอนเริ่มร่าย ทิศของสกิลมาจากทิศเดินหรือทิศที่หันล่าสุด **สกิลไม่มีเล็งอัตโนมัติ**
- **สิ่งที่ sim ยังไม่มีเลย:** กระสุนหรือลูกธนูที่เดินทางได้, พื้นที่ค้างหลายวินาที, ดาเมจต่อเนื่อง (DoT), ตีหลายครั้งต่อสกิล, ทะลุเป้า, ติดตามเป้า, ชะลอหรือผลักศัตรู และบัฟ
  ทีม B ทำกลไกเหล่านี้ใน sim ได้ แต่ต้องได้ตัวเลขทุกค่าเป็น tick และเมตร (ดูข้อ 3.1)
- ศัตรู: พัฟแคป HP 40, ธอร์นลิง HP 55 และบอสปริซึมแบ็ก HP 1000 (2 เฟส) เพลย์เทสต์ agent ใช้เวลาจบด่าน 1:13–1:20
- หัวใจการต่อสู้ (PROJECT_SYNES ข้อ 2) คือ อ่านท่า → หลบ/หลบเพอร์เฟกต์ → ตีสวนตอนศัตรูเสียหลัก → ล่อบอสชนเสา
  ท่าพุ่งชนของบอสเล็งไปที่ตำแหน่งผู้เล่น และบอสจะมึน 2.6 s เมื่อชนเสา
- **ไม่มีบัญชีผู้เล่น ฐานข้อมูล หรือการเก็บความคืบหน้าข้ามรอบ** ถ้าต้องเลือกอาชีพ ตอนนี้ทำได้แค่ต่อรอบเท่านั้น

### 2.2 โมเดล ภาพ และเสียง
- ตัวนักเดินทางสร้างจากสคริปต์ Blender (`tools/blender/build_kit.py` → `synes_kit.glb`) เป็นชิ้น body/head/sword ที่โค้ดขยับเป็นท่า **ไม่มีโครงกระดูก (rig)**
  โมเดลชุดใหม่ได้รับอนุมัติจากเจ้าของ 2026-11-21
- VFX สกิลสร้างจากรูปทรงใน Three.js และใช้พูลซ้ำ ผลวัดของ 3 สกิลตอนซ้อนกันคือ +3 draw calls ทั้ง Medium และ Low (`docs/qa/vfx-2b.md`) โดยเพดานจาก DES-001 คือ +5 Medium และ +3 Low
- draw calls ในลานบอสหลัง DES-004 ขั้น 1 คือ low 96 · medium 107 · high 207 เป้าระยะยาวคือต่ำกว่า 40
  **ตัวเลขทั้งหมดมาจาก Chromium + GPU ซอฟต์แวร์ใน container ยังไม่มี FPS จากเครื่องจริง**
- เสียงเป็นเสียงสังเคราะห์ในโค้ด (`src/audio.ts`) ไม่มีไฟล์เสียง
- ไอคอนสกิลตอนนี้เป็น SVG placeholder ส่วนบรีฟ `ui_skill_icons_v01` ยังรอเจ้าของอนุมัติการผลิต

### 2.3 การวางแนวจอ (ภาพอยู่ใน `docs/qa/req003/`)
- เกมออกแบบให้เล่นแนวนอนก่อน (PROJECT_SYNES ข้อ 1) จอเป้าหมายขั้นต่ำคือ 844×390
- ตอนกดเริ่มบนจอสัมผัส เกมขอเต็มจอและขอล็อกแนวนอน (`screen.orientation.lock('landscape')` ใน `src/main.ts`)
- ถ้าถือมือถือแนวตั้ง จะขึ้นการ์ด "หมุนจอเป็นแนวนอนเพื่อเล่นได้สบายที่สุด" และมีปุ่ม "เล่นแนวตั้งต่อ" (`portrait-390x844-a-first.png`)
- **มีผังแนวตั้งอยู่แล้ว** และสลับเองทันทีที่หมุนเครื่อง เพราะใช้ CSS `@media (orientation: portrait)` และฟัง resize
  - ปุ่ม/จอยเล็กลง (×0.8) และย้ายตำแหน่ง ส่วนกล้องกว้างขึ้น (FOV 62 จาก 48) และถอยห่างขึ้น ×1.35
  - **ทีม B เขียนผังนี้เองก่อนมี ADR-007 ทีม A จึงยังไม่เคยตรวจ**
- สิ่งที่เห็นในภาพแนวตั้ง 390×844 (Chromium จำลอง ไม่ใช่เครื่องจริง):
  - ลานบอส: บอส วงเตือนพัด และผู้เล่นเห็นครบ แต่ขอบซ้ายขวาของพัดกวาดเขา (5.2 m) ชนขอบจอพอดี (`portrait-390x844-c-boss.png`)
  - ปุ่มกินพื้นที่ล่างจอประมาณ 200 px ส่วนกล่องคำแนะนำอยู่ใต้แถบ HP ด้านบน (`portrait-390x844-b-play.png`)
  - ภาพเทียบแนวนอน: `landscape-844x390-c-boss.png`
- **ข้อจำกัดของแพลตฟอร์ม (ยังไม่ได้ทดสอบบนเครื่องจริง):**
  - iPhone Safari ไม่รองรับการล็อกแนวจอจากหน้าเว็บ และไม่รองรับเต็มจอสำหรับหน้าเว็บทั่วไป
  - Android Chrome ล็อกแนวได้เฉพาะตอนเต็มจอ
  - ผลคือ **ปุ่มบนหน้าเว็บสั่งหมุนจอจริงของ iPhone ไม่ได้** ถ้าจะมีปุ่มสลับ ปุ่มนั้นทำได้แค่เปลี่ยนผังในเกม หรือหมุนภาพทั้งเกม 90° ด้วย CSS
  - การหมุนด้วย CSS มีผลข้างเคียงทางเทคนิค: ต้องแปลงพิกัดนิ้วทุกจุด, safe area และ notch จะอยู่ผิดด้าน, แถบที่อยู่ของเบราว์เซอร์และแป้นพิมพ์จะยังเป็นแนวตั้ง
    และถ้าผู้ใช้เปิดล็อกการหมุนของเครื่องไว้ เกมจะไม่รู้ว่าเครื่องถูกถือแนวไหน

## 3. ข้อจำกัดทางเทคนิคและกฎที่ล็อกไว้ (ออกแบบในกรอบนี้ หรือระบุชัดว่าขอเปลี่ยนกฎข้อไหน)
**ทุกข้อ**
- **ส้ม #FF7A1A และแดง #FF3355 สงวนไว้ให้วงเตือนศัตรูเท่านั้น** VFX ของผู้เล่นใช้ไม่ได้ ซึ่งกระทบสกิลธาตุไฟโดยตรง
- วงเตือนวาดทับทุกอย่าง (ADR-005) VFX ของผู้เล่นต้องไม่ทำให้วงเตือนอ่านยากขึ้น และไม่มีแฟลชเต็มจอ (DES-001 §3)
- palette: lumen #5CF2E6 · violet #A78BFA · blossom #FF9EC7 · gold #FFC857 · teal #2BB3A3
- ปุ่มต้องไม่บังตัวละคร ศัตรู หรือวงเตือน
- ตัวละคร ภาพ และ UI ต้องเป็นต้นฉบับ ห้ามเลียนแบบอาชีพหรือสกิลของเกมที่มีอยู่
- asset ใหม่ทุกชิ้น (โมเดล ไอคอน ภาพ) ต้องมีบรีฟใน `docs/handoff/` และให้เจ้าของอนุมัติก่อนใช้จริง (ADR-006) ระหว่างรอ ทีม B ใช้ placeholder ที่ลงทะเบียนไว้

**3.1 อาชีพและสกิล (sim)**
- ผลทุกอย่างคำนวณใน sim แบบ deterministic 30 Hz เพราะ server จำลองซ้ำจาก input log (ADR-002)
  **ขอตัวเลขในรูปที่ใส่ `tuning.ts` ได้** เวลาเป็น tick (L-001: วินาทีที่ปัดแล้วทำให้ tick คลาด) ระยะเป็นเมตร มุมเป็นค่า cos หรือเวกเตอร์ (sim ห้ามใช้ trig)
- ถ้าเป็นกระสุนหรือลูกธนู ต้องได้ความเร็ว (m/tick), รัศมีชน, ระยะสูงสุด, ทะลุกี่เป้า, ชนเสาหรือกำแพงแล้วเป็นอย่างไร และเลือกเป้าแบบไหน
- ถ้าเป็นพื้นที่ค้างหรือดาเมจต่อเนื่อง ต้องได้ระยะเวลา (tick), จังหวะโดน (ทุกกี่ tick) และเพดานจำนวนครั้งต่อเป้า
- input เก็บปุ่มได้ 8 บิตและใช้ครบแล้ว (โจมตี, หลบ, สกิล 1–3, ยา, ลองใหม่, อัลติ)
  - ถ้าทุกอาชีพมีปุ่มเท่าเดิม ใช้รูปแบบเดิมได้เลย
  - ถ้าต้องการปุ่มเพิ่ม กดค้างเพื่อชาร์จ หรือลากเพื่อเล็ง ทีม B ขยายรูปแบบ input ได้ (เป็นงานเทคนิค) ทีม A ระบุแค่วิธีควบคุมที่ต้องการ
- การเลือกอาชีพต้องเป็นส่วนหนึ่งของ run variant ที่ server ตรวจ ทีม B ทำส่วนนี้เอง
- มีเทสต์ความยุติธรรมของเวลาเตือนอยู่แล้ว ถ้าอาชีพใหม่ทำให้ต้องเปลี่ยนค่าของศัตรูหรือบอส ให้ระบุไว้ด้วย

**3.2 VFX "อลังการ" กับงบประสิทธิภาพ**
- ทุกวันนี้ต้องเล่นได้บนมือถือผ่านลิงก์ และเพดาน VFX ผู้เล่นตาม DES-001 คือ +5 draw calls (Medium) / +3 (Low)
- ถ้าความอลังการต้องใช้งบเกินนี้ ขอให้ระบุงบต่อสกิลแยกแต่ละ tier (Low/Medium/High) และระบุว่าส่วนไหนตัดได้บน Low
- เอฟเฟกต์แบบ post-process เช่น bloom ตอนนี้ยังไม่มี (มติทีมเดิมให้ทำเฉพาะ tier สูงในรอบ 3)

**3.3 การวางแนวจอ**
- ทีม B ทำผังที่สลับตามการถือเครื่องได้ทันที (โครงมีแล้ว) หรือทำปุ่มเล็กได้ทั้งสองแบบ แต่ข้อจำกัดของ iPhone อยู่ในข้อ 2.3
- ถ้าแนวตั้งเป็นโหมดที่รองรับเต็มตัว กฎ "ออกแบบแนวนอนก่อน" ใน PROJECT_SYNES ข้อ 1 จะเปลี่ยน ต้องให้เจ้าของยืนยัน (Q55)
- ผังปุ่มแนวตั้งต้องรองรับปุ่ม 7 ปุ่มขึ้นไปตาม DES-001 และ skin ปุ่มตาม DES-002

## 4. สิ่งที่ทีม B ต้องได้กลับ (ใน `DES-005-...md`)
1. **แนวคิดอาชีพ** นักเวทและนักธนู: ชื่อไทย/อังกฤษ, บทบาท, อาวุธ, silhouette, สีประจำอาชีพในกรอบ palette และวิธีที่แต่ละอาชีพเข้ากับหัวใจการต่อสู้ (รวมการล่อบอสชนเสาเมื่อยืนไกล)
2. **โจมตีปกติ + สกิลทุกช่อง + อัลติ** ของแต่ละอาชีพ: ตัวเลขตามข้อ 3.1, ลำดับ tick ของท่า, VFX ทีละช่วง (สี รูปทรง ระยะเวลา งบแต่ละ tier), เสียง และ silhouette ของไอคอน
3. **ค่าพื้นฐานของอาชีพ** (HP, ความเร็ว, หลบ, ยา) ว่าต่างจากนักเดินทางไหม และเป้าสมดุล (เวลาจบบอส, ดาเมจที่โดน)
4. **หน้าเลือกอาชีพ**: เลือกตอนไหน, เปลี่ยนได้เมื่อไร (ก่อนเริ่ม / หลังตาย / ระหว่างรอบ) และหน้าตา
5. **การวางแนวจอ**: ปรับอัตโนมัติหรือมีปุ่ม (ถ้ามีปุ่ม อยู่ตรงไหนและทำอะไร), ผังปุ่มแนวตั้งที่ 390×844 และจอใหญ่, กรอบภาพกล้องแนวตั้ง และจะเอาการ์ด "หมุนจอ" ไว้หรือไม่
6. **บรีฟ asset** ตาม `docs/handoff/TEMPLATE.md`: โมเดลอาชีพ 2 ตัว, ไอคอนสกิล และ VFX ที่ต้องผลิต
7. **ลำดับงานและเกณฑ์ตรวจรับ** ทีม B จะส่งคลิป ภาพ และตัวเลข draw calls กลับตามนี้
