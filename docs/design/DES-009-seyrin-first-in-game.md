# DES-009 · เซย์รินเข้าเกมครั้งแรก

**ทีม A (Codex) · 2026-11-28 · ฉบับ 1 · ตอบ REQ-009 Q1–Q5**

เลือก **G1 ตัวเดี่ยวตาม DES-007 เป็นต้นทางเดียว** และเริ่มงาน Engineering คู่ขนานกับงานผลิต โดยส่ง **ตัวอย่างในฉากบนเครื่องเจ้าของ 6 คลิปก่อน** แล้วส่งเวอร์ชันเล่นครบ `ninja-roam-1` พร้อม 20 คลิปตามแบบเดิม การเห็นตัวอย่างครั้งแรกไม่ต้องรอผลิตครบทุกท่า แต่ไม่เรียกตัวอย่างนั้นว่าเกมนินจาที่เล่นเสร็จแล้ว

เอกสารนี้เป็นแผนและข้อตกลงส่งงาน รอบนี้เขียนไฟล์นี้ไฟล์เดียว ไม่ผลิต/แก้ asset ไม่เรียก Blender/MCP ไม่ใช้บัญชี/เครดิต ไม่แก้โค้ด ไม่ commit/push และไม่เปิดลิงก์เผยแพร่ การผลิตและ implementation ที่ระบุด้านล่างเป็นงานรอบถัดไป

## 1. ฐานตัดสินและสิ่งที่ตรวจเอง

- อ่าน REQ-009, DES-007 ฉบับ 4 โดยเฉพาะ §3/6–8/10–11, คำตอบเจ้าของใน REQ-007, ADR-002/005/007/011/013/014, asset pipeline/contract, README ขั้นตอนออกแบบ และองค์ความรู้เรื่องเครื่องมือ/ที่มาแล้ว
- **เจ้าของตัดสินแล้ว:** อนุมัติแบบ DES-007 วันที่ 2026-11-28; เซย์รินแทน Wayfarerในกติกาใหม่ ชื่อ/สี/ท่า/สกิล/ค่าพื้นฐาน/G1 ใช้ตามนั้น กระโดดคือ “ยกตัวตอนฟัน” (`canJump=false`) และไม่มีระบบปัดดาบ ไม่ขอเลือกเรื่องเหล่านี้ซ้ำ
- **ตรวจโค้ดเอง:** `makeHero()` เรียก `kitCharacter('hero', ['hero_body', 'hero_head', 'hero_sword'])`; ตัวเดิมเป็นชิ้นแข็ง โค้ด `lambertize()` ของเส้นทาง kit ไม่คัดลอก texture map จึงใช้เป็นทางโหลดเซย์รินตรง ๆ ไม่ได้ `fromKit().clone(true)` ไม่ใช่สัญญา clone skeleton ของตัวใหม่ ต้องมีทางโหลด/ตัวเล่นแยกโดยทีม B
- **ข้อมูลจากทีม B ยังไม่ได้ตรวจไฟล์จริงโดยทีม A:** ชีต GLB เดิมประมาณ 53 MB/~49k tris, ไม่มี rig/ท่า, G1 ยังไม่เจน/inbox ยังไม่มีไฟล์, เครื่องเจ้าของมี Blender 5.3 + MCP 2.3.3 และ hy3d Terms เปิดจากเครื่องทีม B ไม่ได้ รอบนี้ไม่ได้เปิด GLB ไม่ทดสอบ Blender/เกม ไม่วัดเวลาผลิตหรือ perf และไม่ได้ตรวจเงื่อนไขเว็บใหม่
- worktree มีงาน DES-008 รอบ 3 ที่กำลังแก้อยู่แล้ว แผนนี้ไม่อนุญาตให้เขียนทับงานนั้น PM ต้องแบ่งเจ้าของไฟล์ก่อนเริ่ม Engineering ที่แตะ `src/main.ts`/HUD/QA ร่วมกัน

## 2. Q1 — ทางเร็วที่สุดและขอบเขตเวอร์ชันแรก

### 2.1 ต้นทาง: เจน G1 หนึ่งชิ้น ไม่รื้อชีตเป็นสายผลิตคู่กัน

ใช้ **G1 ตัวเซย์รินเดี่ยว A-pose มือว่าง ไม่มีดาบ/ฝัก** ตาม DES-007 §10.2 ต่อไป เหตุผลคือชีตเดิมยังมีปัญหาที่ไม่ทราบทั้งผิวซ่อน การเชื่อมชิ้น UV และสิทธิ์ ไม่ได้เป็นตัวละคร rigged ที่เพียงเปลี่ยนนามสกุลแล้วใช้ได้ การแยก/ซ่อมก่อนตรวจอาจเสียแรงซ้ำกับ G1 แผนที่เร็วขึ้นจึงมาจากการทำงานคู่ขนานและส่งก่อนครบชุด ไม่ใช่การอ้างว่าชีตพร้อมใช้

ชีตเดิม `c9ca59b6439c1e54f5801b01124e367d.glb` ใช้เป็นอ้างอิงส่วนตัวเรื่องหน้า/ผม/ชุด/อาวุธเท่านั้น **ห้ามแก้ต้นฉบับและห้ามเข้า repo/build** ตรวจสิทธิ์ภาพอ้างอิงก่อนอัปโหลดด้วย คาตานะ/ฝักเก็บรูปทรงใน Blender ตามแบบเดิม ไม่ต้องเจนเพิ่ม ถ้าใช้ geometry/texture ที่แยกมาจากชีตจริง ต้องมีที่มา/สิทธิ์ของชิ้นนั้นผ่านก่อน ไม่ถือว่าสิทธิ์ G1 ครอบคลุมชีตย้อนหลัง

ถ้า G1 หรือเงื่อนไขเว็บติดขัด ให้ทีม B ทำโครงระบบและทดสอบด้วย placeholder เดิมต่อ ส่วนผลิต/นำเข้า G1 หยุดเฉพาะส่วนที่ติด **ไม่สลับไป rig ชีตเองและไม่ปั้นตัวละครใหม่จากศูนย์** ทางเปลี่ยนต้นทางให้ทีม A ตัดสินเมื่อมีผลตรวจจริงและให้เจ้าของอนุมัติผลกระทบ

### 2.2 สองจุดส่งมอบที่ต้องเรียกชื่อให้ตรง

| จุดส่ง | สิ่งที่ต้องมี | สิ่งที่ยังไม่ถือว่าส่งสำเร็จ |
|---|---|---|
| **P1 — เซย์รินตัวอย่างในฉากบนเครื่องเจ้าของ** (เวอร์ชันแรกที่เห็นในเอนจินเกม) | G1 ที่เก็บรูป/texture/ขนาดแล้ว ตัวเดียวสูง 1.5 ม., ดาบ/ฝัก, rig **45 bones** และ sockets/anchorsครบ; **6 คลิป** ใน §3; โหลดใน Three.js กับฉาก/กล้อง/แสงเกมเดิมได้ | ยังไม่ใช่ run ที่เล่นต่อสู้ได้ ไม่มีผลแพ้ชนะ/รางวัล ไม่ใช้สกิล Wayfarerแทน ไม่มีข้ออ้างว่าผ้าพลิ้วหรือครบ DES-007 แล้ว |
| **P2 — เซย์รินเล่นได้ครบตามแบบ** | mesh/rigเดิม + **20 คลิปครบ** ตาม DES-007 §8.2, ruleset `ninja-roam-1` ทั้งชุด, 3 สกิล/อัลติ/mark/meter, solverผ้า, VFX/HUD, QA/replay/อนุมัติ asset | ยังไม่เปลี่ยนค่าเริ่มที่เผยแพร่หรืออัปเดต Pagesอัตโนมัติ การเผยแพร่ต้องให้เจ้าของอนุมัติแยก |

**ข้อกำหนด P1:** เป็นโหมดตรวจภาพเฉพาะเครื่องเจ้าของ/loopback ใน development ไม่ใช่ทางเข้าหนึ่งของเกมปกติ แสดงข้อความ “ตัวอย่างเซย์ริน · ยังไม่ใช่รอบเล่น” ใช้ฉากเดิมที่จุดเริ่ม/กล้องเดิม ไม่ออกแบบฉากหรือกล้องใหม่ ไม่มีศัตรูกำลังโจมตี ไม่เดิน sim/AI ไม่เรียก `/run/start`/`/run/finish` ไม่สร้าง input log/รางวัลและไม่แก้ด่านของ ruleset ใด ปุ่มเกมปกติไม่สั่งต่อสู้ในโหมดนี้

เลือกดู 6 คลิปผ่านเครื่องมือตรวจของทีม B; เริ่มด้วย `idle` คลิป non-loop เล่นครั้งเดียวแล้วกลับ idle, `run` เป็น in-place ไม่ย้ายตัวในโลก, หลบ/พุ่งแสดง pose in-place เช่นกัน จึงไม่ได้พิสูจน์ระยะวิ่ง/iframe/dash ต้องรอ P2 นาฬิกาดูท่าแยกจาก world tick ที่หยุด ใช้เวลาสะสม render ที่ไม่เดินขณะ pause/ซ่อนหน้าและไม่ชดเชยเวลาที่หายไป; แสดงเวลาเป็น tick-equivalent 30 Hz สำหรับตรวจ marker แต่ไม่ส่ง event ดาเมจจำลองเป็นผลเกม

P1 ปิด solverผ้าได้โดยใช้ rest pose ที่ไม่ทะลุตัว; ทีม B อาจทดสอบ solverที่ทำแล้วแยกเปิด/ปิดในเครื่องมือ QA แต่ **static rest ไม่ผ่าน Q4** ของ DES-007 ไม่สร้าง VFXสกิล/ประกายตีโดนปลอมเพื่อให้ดูเหมือนเล่นครบ การทดสอบวงเตือนใช้ fixture ชั้นวาดแยกจากโหมดดูท่า ไม่มีผลต่อสู้

### 2.3 ปรับลำดับจาก DES-007 §11.1 อย่างไร

- คงขั้น 1–3: G1 → เก็บ mesh/texture → rig/weight; ไม่ลด rigเหลือคนละโครง ไม่ส่ง raw 53 MB และไม่ยกเว้นสิทธิ์/งบ/การอนุมัติ
- เมื่อจบ **ขั้น 4 ท่าหลัก 6 ท่า** ให้ export P1 เพื่อเทียบในฉากทันที ไม่รอขั้น 5 ครบ 20 คลิป
- ย้าย **ขั้น 6 Engineering** ให้เริ่มพร้อมขั้น 1: ระบบโหลด/เล่นท่าและ ruleset ทำด้วย placeholder/fixture ก่อน พอไฟล์จริงมาถึงจึงต่อและวัดซ้ำ
- คลิปที่เหลือ 14, ผ้าพลิ้วสมบูรณ์, VFX/เสียง/การเล่นครบชุดเลื่อนได้เฉพาะหลัง P1 และต้องครบก่อน P2 ไม่ลดเกณฑ์สำเร็จของ DES-007
- พักงานกันคัดลอกตามคำสั่งเจ้าของ ไม่ให้ watermark/obfuscation/แพ็กไฟล์/meshopt หรือการเลือกโฮสต์เป็นเส้นทางบังคับก่อน P1; คงการเก็บต้นฉบับส่วนตัวและด่านอนุมัติไว้

## 5. Q3 — ด่านอนุมัติ: บิลด์บนเครื่องไม่นับเหมือนกันทุกกรณี

1. **แบบ:** DES-007อนุมัติแล้ว ไม่รออนุมัติชื่อ/สี/สกิลซ้ำ งานผลิตตามแบบเริ่มในรอบผลิตได้เมื่อมีต้นทางและด่านสิทธิ์ผ่าน เอกสารนี้ไม่ลบข้อห้ามผลิตของรอบเอกสารปัจจุบัน
2. **สิทธิ์/ที่มา:** ก่อนนำ G1เข้าเอนจินแม้ใน P1 ต้องอ่านเงื่อนไขบริการที่ใช้จริงตาม ADR-014/REQ-007ครบและบันทึกผล วันที่ รุ่น/ช่องทาง และสิทธิ์ภาพที่อัปโหลด ตรวจการใช้/แก้ไข/output/เผยแพร่ต่อเชิงพาณิชย์/ขอบเขตพื้นที่จากข้อความจริง ไม่ยืมข้อสรุปlicense open weightsมาแทนเว็บ และไม่ถือว่าฟรี5ชิ้นแปลว่าอนุญาตเผยแพร่ ทีม Bทำทะเบียนเฉพาะข้อมูลปลอดภัย; ข้อความที่ยังคลุมเครือส่งเจ้าของพร้อมข้อเท็จจริง/ผลกระทบก่อนใช้
3. **REVIEWก่อนAPPROVED:** เมื่อสิทธิ์การตรวจภายในผ่านและใบสั่งงานอยู่สถานะREVIEW ทำภาพเทียบP1และทดสอบP2ในบิลด์QAส่วนตัวได้ นี่คือขั้นตรวจassetตามpipeline **ยังไม่ใช่การอนุมัติassetให้เล่นจริง** P1ยังดูท่าอย่างเดียว; P2 QAจึงเริ่มจำลองการต่อสู้/รับinputทดสอบ/เล่นreplayได้ โดยขึ้นข้อความ “เซย์ริน · ทดสอบเพื่อตรวจรับ · ไม่บันทึกผล” และแยกทางเข้าจากrunปกติ ไม่มีรางวัล/ความก้าวหน้าที่นำไปใช้จริง ไม่มีผู้เล่นภายนอก ไม่ส่งผลเข้าระบบจริง การทดสอบclient/serverใช้sim/test endpointที่แยกข้อมูลทดสอบเท่านั้น ไม่อ้างจบrunเพื่อรับรางวัล บันทึกlogได้เป็นหลักฐานQAส่วนตัว ไม่จำเป็นต้องให้เจ้าของอนุมัติไฟล์ที่ยังไม่เคยเห็นก่อนสร้างหลักฐาน แต่ต้องตรวจหลักฐานจริงก่อนผ่านขั้นถัดไป การทดสอบบนมือถือก่อนอนุมัติassetต้องเป็นช่องทางส่วนตัวที่เจ้าของอนุญาตแยก ไม่อัปเดตPagesเพื่อQAเอง
4. **เล่นจริงแม้อยู่ในเครื่อง:** ถ้าผูกassetกับrunใช้งานปกติ ส่งผล/รับรางวัล/บันทึกความก้าวหน้าจริง หรือปล่อยบิลด์ให้ผู้เล่นใช้ ให้ถือเป็น “ใช้จริง” ต้องมีเจ้าของ **APPROVEDไฟล์runtimeรุ่น/hashนั้น** หลังทีม B QA + ทีม Aตรวจแล้ว คำว่าlocalhostไม่ยกเว้นขั้นนี้ ข้อยกเว้นREVIEWข้างต้นจำกัดเฉพาะตรวจรับภายใน ไม่ใช่ตั้งชื่อบิลด์ปกติว่าQAเพื่อข้ามอนุมัติ
