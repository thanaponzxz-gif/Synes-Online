# ลานต่อสู้ปริซึมแบ็ก

ต้นแบบสำหรับตรวจในเกมจากภาพ “SYNES Online Prismatic Crystal Battle HUD” ที่เจ้าของส่งมา

- จัดกล้องแนวนอนไว้ต่ำด้านหลังนักเดินทาง เห็นตัวละครช่วงล่างกลางจอและตัวบอสด้านหน้า ปรับระยะตามตำแหน่งบอสเพื่อรักษาพื้นที่ให้วงเตือน
- ใช้ Blender ปรับนักเดินทางเป็นผมเงิน ผ้าคลุมม่วง และเกราะขอบทอง ปรับปริซึมแบ็กให้มีเกราะหินซ้อนกับผลึกใหญ่ไล่จากฟ้าถึงม่วง รักษาชื่อชิ้นส่วน จุดหมุน และขนาดอ้างอิงของชุด GLB
- ใช้ Three.js ประกอบลานหิน ซากเสา ศาล และผลึกรอบนอก เว้นพื้นที่เล่นเดิมและใช้สีส้มกับแดงสำหรับวงเตือนเดิม
- เก็บ HUD ภาษาไทยพร้อมแถบพลังและปุ่มจากสถานะเกม ใช้ภาพแนบเป็นเป้าหมายด้านองค์ประกอบ สี และรูปทรง
- ตรวจช็อตเปิดสู้และช่วงวงเตือนในเบราว์เซอร์อย่างน้อยหนึ่งขนาดจอมือถือแนวนอน ตรวจการประกอบ GLB ซ้ำจาก Blender และเก็บภาพจากเกมจริงสำหรับเทียบกับภาพแนบ

## งานที่ส่งต่อให้ทีม B

ปรับเฉพาะ shader วงเตือนใน `src/render/fx.ts` ให้ขอบบางและสว่าง พื้นด้านในจางลงจนยังอ่านหน้าบอสและพื้นลานได้ เก็บขอบเขต รูปทรง สีตามระดับอันตราย และการเติมพื้นที่ตามเวลาเดิม รวมถึงการแสดงวงเตือนเหนือฉากตามเดิม

หลังแก้ให้ใช้ภาพจากเกม 1672×941 และ 844×390 ตรวจวงกลม พัด และเส้นพุ่ง จากนั้นวัด FPS และ draw calls บน Android และ iPhone จริงที่กราฟิกระดับต่ำและกลางก่อนอนุมัติใช้จริง ส่วนภาพตัวละครบน HUD และวัสดุผลึกที่ใกล้ภาพอ้างอิงยิ่งขึ้นให้แยกเป็นงานออกแบบของทีม A

## ผลต้นแบบ

- Blender 4.5.3 LTS ส่งออกชุดโมเดล 579.4 KB รวม 15,604 triangles ตรวจด้วย `verify_kit.py` ผ่านโดยไม่มีคำเตือน และส่งออกอิสระอีกครั้งได้ไฟล์ที่ตรงกัน
- Claude Code Sonnet ทีม B ตรวจภาพอ้างอิงและภาพเกมสองขนาด แล้วแก้ shader วงเตือนตามบรีฟในหัวข้อด้านบน
- ภาพจากเกมที่เก็บในเครื่องอยู่ใน `tools/qa/out/prismatic-warning-1672.png` และ `tools/qa/out/prismatic-warning-844.png`
- งานตรวจต่อของทีม B คือวัด FPS และ draw calls ระหว่าง phase 2 บน Android และ iPhone จริง รวมถึงตรวจว่าซากและผลึกริมลานไม่บังตัวละครหรือวงเตือนเมื่อเข้าต่อสู้ด้านข้าง
