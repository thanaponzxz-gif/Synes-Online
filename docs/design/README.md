# ขั้นตอนออกแบบ: ทีม A → ทีม B (ADR-007, CLAUDE.md ข้อ 0)

| ทีม | ใคร | หน้าที่ |
|---|---|---|
| **A** | GPT Codex | ออกแบบหรือเขียนบรีฟทุกงาน (ระบบเกม, สกิลและ VFX, UI/UX, ตัวละคร, มอนสเตอร์, ฉาก, asset) และตรวจผลที่ทีม B ส่งกลับ |
| **B** | Claude (PM + subagent) | ทำตามดีไซน์ใน repo, ทดสอบ และส่งผลกลับ **ไม่ออกแบบเอง** |
| เจ้าของ | คุณหนึ่ง | ส่งต่อระหว่างทีม ตัดสินเมื่อทีมเห็นไม่ตรงกัน และอนุมัติ asset ก่อนใช้จริง |

## ไฟล์
- `REQ-NNN-<หัวข้อ>.md`: **ใบขอออกแบบ** จากทีม B ถึงทีม A
  มีความต้องการของเจ้าของ (ยกคำมาตรง ๆ), ข้อเท็จจริงใน repo, ข้อจำกัดทางเทคนิค, สิ่งที่ทีม B ต้องได้กลับไป และคำถาม **ไม่มีข้อเสนอดีไซน์**
- `DES-NNN-<หัวข้อ>.md`: **ดีไซน์** จากทีม A (Codex commit บน branch `design/<หัวข้อ>` หรือเจ้าของวางในแชตแล้ว Claude บันทึกตามต้นฉบับ)
  ท้ายไฟล์มีหัวข้อ "ผลการทำ (ทีม B)" ไว้ให้ทีม B เติม commit, ภาพ, ผลทดสอบ และจุดที่ต้องให้ทีม A ตัดสิน
- บรีฟ asset ยังอยู่ที่ `docs/handoff/<asset>.md` ตาม `docs/ASSET_PIPELINE.md` (ทีม A เป็นคนเขียน)

## สถานะ
`REQ เปิด` → `DES ได้รับ` → `กำลังทำ` → `ส่งตรวจ` → `ผ่าน` / `แก้` (ทีม A ตัดสิน)
ถ้าระหว่างทำพบว่าต้องเปลี่ยนดีไซน์ หรือดีไซน์ไม่ได้ระบุเรื่องที่ต้องเลือก: ให้หยุดเฉพาะส่วนนั้น บันทึกเป็นคำถามในไฟล์ DES แล้วส่งกลับทีม A **ห้ามเลือกเองแล้วนำไปใช้**
