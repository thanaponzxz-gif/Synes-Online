# REQ-001: สกิลใช้งาน 3 + อัลติ (ล็อก) และระบบโจมตีอัตโนมัติ
**จาก:** ทีม B (Claude) · **ถึง:** ทีม A (GPT Codex) · **วันที่:** 2026-11-20 · **สถานะ:** REQ เปิด
ใบนี้มีความต้องการ ข้อเท็จจริง และข้อจำกัดเท่านั้น **ทีม B ไม่ได้ใส่ข้อเสนอดีไซน์** ตามกฎ ADR-007

## 1. ความต้องการของเจ้าของ (ยกมาตามที่สั่ง 2026-11-20)
1. "ปรับจากแนวคิดเดิม 2 ท่าเป็นสกิลใช้งาน 3 สกิล พร้อมท่าออกสกิลและเอฟเฟกต์อลังการที่ยังอ่านจังหวะสู้บนมือถือได้ อัลติเป็นช่องแยก แสดงสถานะล็อกไว้และรอปลดล็อกภายหลัง เงื่อนไขปลดล็อกยังเปิดให้เสนอ"
2. ~~"เพิ่มหลอดเลือดเหนือมอนสเตอร์ทั่วไป อ่านง่ายบนมือถือและอัปเดตตาม HP จริง"~~
   **ปิดเรื่อง: เจ้าของตัดสิน 2026-11-20 ว่า "ดีแล้วไม่ต้องเปลี่ยน หลอดเลือดค่อยขึ้นตอนตีมอน"** ใช้หลอดเดิมที่ขึ้นเมื่อมอนสเตอร์โดนตี ทีม A ไม่ต้องออกแบบข้อนี้
3. ภาพแนบจากเจ้าของ "เป็นเรฟฟังก์ชันของระบบโจมตีอัตโนมัติ"
   - เป็นภาพหน้าจอจากเกมอื่น จึง**ไม่ได้เก็บไว้ใน repo** เพราะ repo เป็น Public และ UI ของ Synes ต้องเป็นต้นฉบับ
   - ทีม B อ่านฟังก์ชันจากภาพได้ตามตารางด้านล่าง เส้นสีน้ำเงินในภาพตีความว่า "ไม่เอา" **ให้เจ้าของยืนยัน**

| ฟังก์ชันในภาพ | สถานะในภาพ | ทีม B ตีความว่า |
|---|---|---|
| รายการ "มอนสเตอร์ใกล้เคียง" + ตัวกรอง "มอนสเตอร์ทั้งหมด" | ไม่ขีด | ต้องการ |
| ตั้งค่าสกิลอัตโนมัติ (ปุ่ม "ไป") | ไม่ขีด | ต้องการ |
| กดค้างเพื่อเปิดตัวกรอง | **ขีดฆ่า** | ไม่เอา |
| รักษาการต่อสู้อัตโนมัติหลังคืนชีพ (เปิด) | ไม่ขีด | ต้องการ |
| รูปแบบการใช้สกิล: ลำดับ / ลำดับความสำคัญที่แนะนำ | **ขีดฆ่า** | ไม่เอา |
| ขอบเขต AFK (แถบเลื่อน 20 เมตร) + ตัวเลือก "แผนที่ทั้งหมด" / "ตำแหน่งเดิม" | ไม่ขีด | ต้องการ |
| ฟาร์มออฟไลน์ (สวิตช์) | ไม่ขีด | ต้องการ (ดูข้อจำกัด C-3) |
| ปุ่ม "อัตโนมัติ" บนจอต่อสู้ | ไม่ขีด | ต้องการ |

## 2. ข้อเท็จจริงใน repo ตอนนี้ (commit `5047763`)
- **การต่อสู้ของผู้เล่น** (`shared/data/tuning.ts`):
  - โจมตีปกติเป็นคอมโบ 3 จังหวะ
  - หลบ: 0.3 s, ช่วงอมตะ 0.3 s, คูลดาวน์ 0.55 s
  - สกิล 1 อัน **Chime Burst / ระฆังสะท้อน**: ร่าย 0.35 s, รัศมี 3.6 m, ดาเมจ 34, คูลดาวน์ 8 s, ขัดจังหวะศัตรูที่กำลังชาร์จได้
  - หลบเพอร์เฟกต์: ตีครั้งถัดไป ×1.5 และคืนคูลดาวน์สกิล 2 s
- **ปุ่มบนจอ** (ขวาล่าง): โจมตี (ใหญ่), หลบ, สกิล, ยา (2 ขวด)
  - ขนาด `--btn` = 78–104 px (จอเตี้ยกว่า 420 px ใช้ 78 px) และจอยลอยอยู่ครึ่งซ้าย
  - ปุ่ม/จอยจะโปร่ง 35% เมื่อมีวงเตือน บอส หรือเสาอยู่ใต้ (`3389f98` ทำก่อน ADR-007 ส่งให้ตรวจใน REQ-002)
- **หลอดเลือดมอนสเตอร์ทั่วไปมีอยู่แล้ว ขึ้นเมื่อโดนตี** (`e.hp < e.maxHp`) เจ้าของยืนยันให้ใช้แบบนี้ต่อ
  - ขนาด 44×6 px สีแดงชมพู #ff6b7a อยู่เหนือหัว อัปเดตตาม HP จริงทุกเฟรม (`src/ui/hud.ts`)
  - บอสใช้แถบใหญ่ด้านบนจอแยกต่างหาก
- **มอนสเตอร์:** พัฟแคป HP 40, ธอร์นลิง HP 55 และบอสปริซึมแบ็ก HP 1000 (2 เฟส)
- **ระบบอัตโนมัติ:** ยังไม่มีสำหรับผู้เล่น มีแค่ "บอท" ที่ใช้ทดสอบ (`tests/bot.ts`, `?bot`) ซึ่งสร้าง input แทนนิ้ว
- ไม่มีบัญชีผู้เล่น ไม่มีฐานข้อมูล และไม่มีการเก็บความคืบหน้าข้ามรอบ (backlog ข้อ 7 ยังไม่ทำ)
- เล่นบน iPhone ผ่าน GitHub Pages ได้แล้ว (เจ้าของยืนยัน 2026-11-20) แต่ยังไม่มีตัวเลข FPS

## 3. ข้อจำกัดทางเทคนิคและกฎที่ล็อกไว้ (ทีม A ต้องออกแบบให้อยู่ในกรอบนี้ หรือระบุชัดว่าขอเปลี่ยนกฎข้อไหน)
**ทุกข้อ**
- **สีส้ม #FF7A1A และแดง #FF3355 สงวนไว้ให้วงเตือนการโจมตีเท่านั้น** ห้ามใช้ใน VFX สกิล หรือ UI อื่น
- วงเตือนของศัตรูวาดทับทุกอย่าง (ADR-005) VFX ของผู้เล่นต้องไม่ทำให้วงเตือนอ่านยากขึ้น
- ปุ่มต้องไม่บังตัวละคร ศัตรู หรือวงเตือน (PROJECT_SYNES ข้อ 1) จอเป้าหมายขั้นต่ำคือแนวนอน 844×390
- palette: lumen #5CF2E6 · violet #A78BFA · blossom #FF9EC7 · gold #FFC857 · teal #2BB3A3
- งบประสิทธิภาพ: draw calls ระหว่างเล่นตอนนี้ 39–95 (tier medium) โดยมีเป้าระยะยาวต่ำกว่า 40
  ขอให้ VFX ระบุงบต่อสกิล (จำนวนอนุภาค/draw call) และแบบลดสำหรับ tier low
- โมเดล 3D เป็น .glb, ภาพ UI เป็น .png และทุก asset ต้องมีบรีฟใน `docs/handoff/` ตาม `docs/ASSET_PIPELINE.md` รวมถึงการอนุมัติของเจ้าของ

**A. สกิล 3 + อัลติ**
- A-1 ผลของสกิล (ดาเมจ ระยะ รูปทรง เวลาร่าย คูลดาวน์ ช่วงอมตะ การขัดจังหวะ ฯลฯ) ต้องคำนวณใน sim แบบ deterministic 30 Hz
  เพราะ server จำลองซ้ำจาก input log เพื่อตัดสินผลและรางวัล (ADR-002) **ขอตัวเลขทั้งหมดในรูปแบบที่ใส่ `tuning.ts` ได้**
  ตัวเลขเชิงมุมขอเป็นค่า cos หรือเวกเตอร์ เพราะ sim ห้ามใช้ trig
- A-2 ท่าออกสกิลและ VFX เป็นภาพอย่างเดียว ไม่มีผลต่อการตัดสินใน sim (ถ้าต้องการให้ท่าไหนมีช่วงเวลามีผล เช่น ช่วงร่ายที่ถูกขัดได้ ให้ระบุเป็นตัวเลขใน A-1)
- A-3 input ตอนนี้เก็บปุ่มได้ 5 บิต (โจมตี, หลบ, สกิล, ยา, ลองใหม่) การเพิ่มปุ่มต้องขยายรูปแบบ input ซึ่งทีม B ทำได้ (งานเทคนิค) ทีม A ไม่ต้องออกแบบส่วนนี้
- A-4 เงื่อนไขปลดล็อกอัลติ: ตอนนี้ยังไม่มีการเก็บความคืบหน้าข้ามรอบ
  ถ้าเงื่อนไขต้องอาศัยความคืบหน้า (เลเวล ไอเทม ภารกิจ) ต้องมีระบบบัญชีหรือการบันทึกที่ server ก่อน ซึ่งเป็นงานใหญ่และต้องให้เจ้าของอนุมัติ (ใช้บริการ DB/โฮสต์)
  ถ้าเงื่อนไขอยู่ภายในรอบเดียว (เช่น สิ่งที่เกิดระหว่างเล่น) sim ตรวจได้ทันที
- A-5 จำนวนปุ่มรวมจะเป็นอย่างน้อย 7 (โจมตี, หลบ, สกิล ×3, อัลติ, ยา) ขอผังปุ่มที่ระบุตำแหน่งและขนาดบนจอ 844×390 และจอใหญ่

**C. ระบบโจมตีอัตโนมัติ**
- C-1 ทำได้ในรูป "ตัวสร้าง input" ฝั่ง client แบบเดียวกับบอททดสอบ server จึงยังตัดสินผลจาก input log ได้เหมือนเดิม (ADR-002 ไม่ต้องเปลี่ยน)
- C-2 ขัดกับหัวใจการต่อสู้ที่บันทึกไว้หรือไม่: "อ่านท่า → หลบ/หลบเพอร์เฟกต์ → ตีสวน → ล่อบอสชนเสา" (PROJECT_SYNES ข้อ 2) **ขอให้ทีม A ตัดสินว่าโหมดอัตโนมัติหลบเองหรือไม่ และใช้ได้ที่ไหน** (มอนสเตอร์ทั่วไป / บอส)
- C-3 "ฟาร์มออฟไลน์" (ได้รางวัลตอนไม่ได้เปิดเกม) ต้องมีบัญชีผู้เล่น ฐานข้อมูล และ server ที่คำนวณรางวัลตามเวลา ตอนนี้ยังไม่มีทั้งหมด
  และกฎโปรเจคห้ามสร้างระบบ MMORPG ล่วงหน้าก่อน slice สนุก **ขอให้ทีม A/เจ้าของตัดสินว่าอยู่ในรอบนี้หรือเลื่อนไป**
- C-4 "ขอบเขต AFK" และ "แผนที่ทั้งหมด": ตอนนี้มีแผนที่เดียวเป็นทางเดินเส้นตรงไปลานบอส
- C-5 "รักษาการต่อสู้อัตโนมัติหลังคืนชีพ": ตอนนี้ตายแล้วเกิดใหม่ที่จุดเช็กพอยต์

## 4. สิ่งที่ทีม B ต้องได้กลับ (ใน `DES-001-...md`)
1. รายละเอียดสกิล 3 อัน + อัลติ: ชื่อ (ไทย/อังกฤษ), บทบาท, ตัวเลขตาม A-1, ลำดับเฟรมของท่าออก, VFX (สี รูปทรง ระยะเวลา งบ) และไอคอน
2. ผังปุ่มตาม A-5 รวมถึงหน้าตาสถานะ "ล็อก" ของอัลติ และเงื่อนไขปลดล็อก (หรือระบุว่ายังไม่กำหนด)
3. ขอบเขตระบบอัตโนมัติรอบนี้ (ฟังก์ชันไหนเอา/ไม่เอา) พฤติกรรม (เดิน เลือกเป้า ใช้สกิล หลบ ดื่มยา) และหน้าตั้งค่า
4. บรีฟ asset ที่ต้องผลิต (โมเดล/ไอคอน/VFX) ตามรูปแบบ `docs/handoff/TEMPLATE.md`
5. เกณฑ์ตรวจรับ (ทีม B จะทดสอบตามนี้แล้วส่งผล ภาพหน้าจอ และวิดีโอ/ภาพจากเพลย์เทสต์กลับ)

## 5. คำถามที่ยังเปิดอยู่
- คำว่า "แนวคิดเดิม 2 ท่า" หมายถึงอะไร (ทีม B เข้าใจว่าเป็นโจมตีปกติ + สกิล 1 อัน) ยังไม่ยืนยัน
- ฟังก์ชันในตารางข้อ 1.3 ที่ทีม B ตีความถูกไหม
- ลำดับความสำคัญระหว่าง 2 เรื่องนี้ กับแผนรอบ 2-B เดิม (`docs/team/round-2B-plan.md`)
