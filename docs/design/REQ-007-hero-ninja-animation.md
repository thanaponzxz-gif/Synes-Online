# REQ-007: ตัวละครนินจา (Hero 001) เล่นได้ในเกม พร้อมท่า สกิล rig และ texture
**จาก:** ทีม B (Claude PM) · **ถึง:** ทีม A (GPT Codex), Codex รุ่น 6.1 ขึ้นไป (งานท่า/rig/texture ตาม ADR-013) และเจ้าของ · **วันที่:** 2026-11-27 · **สถานะ:** REQ เปิด
ใบนี้มีความต้องการ ข้อเท็จจริง ข้อจำกัด และคำถามเท่านั้น **ไม่มีข้อเสนอดีไซน์**

## 1. ความต้องการของเจ้าของ (2026-11-27, ยกคำมาตรง ๆ)
- "เรียกดีไซเนอมาดูแลเรื่องตัวละคร ทำยังไงก็ได้ให้ได้ตัวละครนี้และอนิเมชั่นและสกิลที่สวยงาม"
- "ให้สั่งให้ Codex (โมเดลที่เหมาะสม 6.1 ขึ้นไป) รับผิดชอบงานของอนิเมชั่น และทั้งเก็บรายละเอียด texture หรือ rig และถ้ามีผ้าคลุมสีแดง สามารถทำให้เคลื่อนไหวอย่างธรรมชาติพริ้วไหวได้หรือไม่ ถามทีม"
- ผ้าที่หมายถึง: "ผ้าพันคอสีแดงในรูปต้นแบบและตรงเอว"

## 2. ข้อเท็จจริง
**ไฟล์ต้นฉบับ** (อยู่บนเครื่องเจ้าของเท่านั้น ไม่อยู่ใน repo เพราะเจ้าของสั่งห้ามนำ Hero 001 ขึ้น repo สาธารณะ 2026-11-23)

- เป็น **ชีตตัวละคร** ไม่ใช่ตัวเดียว: ตัวใหญ่ด้านหน้าซ้าย 1 ตัว (ยืนแขนแนบลำตัว กำหมัด ผ้าพันคอปลายยาวปลิวไปด้านข้าง), ตัวเล็กหันมุมต่าง ๆ 4 ตัว (กางแขน A-pose), ชิ้นส่วนแยก, หัว 5 หัว และดาบคาตานะ รวมอยู่ใน mesh เดียว
- หน้าตา: จิบิ ผมเงิน ตาแดง ผ้าพันคอแดงปลายยาว ผ้าคาดเอวแดงผูกเป็นปมมีพู่ ฝักดาบแดงสะพายหลัง ชุดดำ/เทา
- ไฟล์ `Downloads/aca1a3fe….glb` (2026-11-25) เป็นตัวละครอื่น (สัตว์มีเขากวางถือไม้เท้ากระดิ่ง) ไม่เกี่ยวกับใบนี้
- ประวัติ: Hero 001 มาจาก GPT + Tripo (`PENDING_QUEUE.md` P1) · แผนเดิม 2026-11-23 คือเจนใหม่จากภาพตัวละครเดี่ยวด้วย Tripo (ยังไม่ได้ทำ)

**เกมตอนนี้**
- ผู้เล่นคือ Wayfarer สูง 1.5 ม. ประกอบจาก 3 ชิ้น `hero_body`, `hero_head`, `hero_sword` (`docs/art/ASSET_CONTRACT.md`) ขยับด้วยโค้ดทีละชิ้น (`src/render/view.ts`) **ยังไม่มีระบบเล่นท่าจากกระดูก**

- ตัวตนของโลก: Wayfarer ผ้าพันคอ teal ถือ Chime Blade (`PROJECT_SYNES.md` ข้อ 2) · **สีแดง #FF3355 และส้ม #FF7A1A สงวนไว้ให้วงเตือนการโจมตีเท่านั้น**
- Blender MCP พร้อมใช้บนเครื่องเจ้าของทั้งฝั่ง Claude Code และ Codex (`mcp-for-blender` 2.3.3, safe mode, ปิด telemetry) · Blender 5.3

## 3. ข้อจำกัดทางเทคนิค
- three.js r187 โหลด glTF ที่มีกระดูก (skinned mesh) และ animation clip ได้ แต่เกมต้องเพิ่มตัวเล่นท่าใหม่ (ทีม B เขียน)
- ผลการต่อสู้มาจาก sim 30 Hz (`shared/`) ท่าเป็นภาพเท่านั้น จังหวะง้าง/ตี/ฟื้นของแต่ละท่าต้องตรงกับเวลาใน `shared/data/tuning.ts` (เช่น หลบ 0.3 วิ, Chime Burst ร่าย 0.35 วิ) ถ้าต้องเปลี่ยนเวลาเหล่านี้ถือเป็นการเปลี่ยนกติกา (ทีม A ตัดสิน และขึ้น ruleset ใหม่)
- ผ้าพลิ้วเป็นภาพฝั่ง client เท่านั้น ไม่กระทบผลต่อสู้ (ADR-002) วิธีที่เอนจินรองรับได้:
  - อบท่าผ้าใน Blender ลงกระดูก/shape key ของแต่ละ clip: ไม่กินเครื่องตอนเล่น แต่ผ้าไม่ตอบสนองเมื่อเปลี่ยนทิศหรือเปลี่ยนท่ากลางคัน
  - กระดูกผ้าเป็นโซ่ แล้วคำนวณสปริงตอนเล่น: ผ้าตอบสนองการเคลื่อนไหวจริง ใช้ CPU เพิ่มเล็กน้อย ทีม B เขียนโค้ด
  - แกว่งด้วย shader: เบาที่สุด แต่แค่ไหว ไม่ตอบสนองการเคลื่อนที่
  - กระดูกยิ่งน้อยยิ่งเบาบนมือถือ (โดยเฉพาะกระดูกผ้า)
- งบภาพปัจจุบัน (`lane/free-roam`, medium, SwiftShader): tris 91–93k, draw calls 48–52 · เพดาน Golden Reference draw calls low 56 / medium 60 · material แต่ละชิ้นของตัวละคร = draw call เพิ่ม
- ขนาดไฟล์และ texture มีผลกับเวลาโหลดบนมือถือ (เกมเปิดจากลิงก์ ไม่ติดตั้ง) · Android / iPhone ยังไม่ได้วัดกับตัวละครที่มี texture
- อาวุธและ VFX ต้องมีจุดยึดที่ตั้งชื่อชัดเจน (กระดูกหรือ node ของมือ/ใบดาบ) แทน `hero_sword`
- ไฟล์ที่ใช้ในเกมจะอยู่ในบิลด์ที่เปิดเล่นได้สาธารณะ (Artifact/Pages) แม้ต้นฉบับจะไม่ขึ้น repo
- บริการที่ต้องใช้บัญชีหรือเครดิต (Tripo, Meshy, Mixamo) ต้องให้เจ้าของอนุมัติก่อน (CLAUDE.md ข้อ 6) · ทางที่ไม่มีค่าใช้จ่ายคือ Blender
- ไฟล์ส่งงานวางที่ `assets/_inbox/` ตั้งชื่อ `ประเภท_ชื่อ_vNN` บันทึกที่มา (เครื่องมือ, prompt, license) ตาม `docs/ASSET_PIPELINE.md`

## 4. สิ่งที่ทีม B ต้องได้กลับไป
- ดีไซน์ (DES) ของตัวละคร: บทบาท ชุดท่า สกิล VFX และสี
- ไฟล์ glb ที่มีกระดูกและท่า พร้อมรายการ: ชื่อ clip, ความยาว, ท่านั้นใช้กับการกระทำไหนในเกม, ชื่อกระดูก/จุดยึด, ขนาด texture, จำนวน tris/material
- วิธีทำผ้าพลิ้วที่เลือก และค่าที่ต้องใช้ (ถ้าเลือกคำนวณตอนเล่น เช่น ความแข็ง/การหน่วงของสปริงต่อกระดูก)
- ภาพหรือคลิปเทียบสำหรับให้เจ้าของอนุมัติ
