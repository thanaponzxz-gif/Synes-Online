## 1. หลักร่วม
- 30 tick/s. Tick 0 คือรับปุ่มที่พร้อม; hit ใน tick ที่ระบุ; cooldown เริ่ม tick 0. ทิศและตำแหน่งล็อกที่ tick 0 เว้นกระสุนที่เคลื่อนจากจุดกำเนิดตามแนวนั้น. ใช้เวกเตอร์ XZ หน่วย; ตรวจเป้าด้วย dot และระยะกำลังสอง ไม่มี trig ใน sim. ขอบ collision นับว่าโดน. หนึ่ง cast ไม่ทำดาเมจเป้าเดียวเกินจำนวนที่ระบุ.
- ใช้ปุ่มเดิม: ตี, หลบ, สกิล 1–3, อัลติ, ยา; ไม่มีชาร์จ/ลากเล็ง. กดเดินกำหนดทิศ; เมื่อไม่เดินใช้ทิศหันล่าสุด. เฉพาะการตีปกติยิงไกลเลือกศัตรูที่มีชีวิตใกล้สุดในกรวยหน้า `dot >= 0.5` และระยะเล็งที่กำหนด; เสมอกันเลือก ID ต่ำสุด. สกิลล็อกทิศเอง ไม่ติดตามเป้า. ถ้าไม่มีเป้าตีปกติไปตามทิศหัน. เสา/ผนังบัง projectile; ไม่ทะลุ geometry. ท่าพื้นที่ไม่ข้ามผนัง.
- คงกฎหลบ 9 tick อมตะ 9 tick, cooldown 17 tick (variant 26 คงเป็นการทดลอง), ยา 2 ขวด +45 HP, perfect dodge ×1.5 กับการตีปกติครั้งถัดไปและคืน Chime เฉพาะ Wayfarer. Mage/Archer ไม่รับการคืน Chime; perfect dodge ให้ ×1.5 การตีปกติครั้งถัดไปเหมือนกัน. การเริ่ม cast ใช้ cooldown ทันที; หลบยกเลิกก่อน hit แล้วไม่มี damage แต่ cooldown คง; หลัง hit หลบตัด recovery ได้. ไม่มีสกิลให้ i-frame, stun, push หรือเปลี่ยน boss AI.
- ตำแหน่งตีไกลทำให้ล่อบอสชนเสายาก: boss charge ยังล็อกตำแหน่งผู้เล่นเดิม; ช่วง charge ต้องยืนหลังแนวเสาแล้วหลบออกด้านข้าง. อย่าเพิ่มระยะการเล็ง charge. คุมให้ศัตรูและวงเตือนเป็นสิ่งที่เด่นที่สุด: สี #FF7A1A/#FF3355 สงวนให้คำเตือน, คำเตือนวาดเหนือ VFX ทั้งหมด, ไม่มี flash เต็มจอ.

**กฎ projectile:** ก้าวแบบ swept segment จากตำแหน่งก่อนถึงหลังในแต่ละ tick ป้องกันทะลุเป้า; collision เร็วสุดชนะ, เวลาเสมอเสา/ผนังชนะศัตรู, ศัตรูเสมอกันเลือก ID; เป้าที่โดนแล้วใน cast เดียวกันไม่โดนซ้ำเกินเพดาน. Projectile หลุดระยะ/ชนผนัง/ครบเป้าแล้วทำลายตาม tick. บันทึก event hit/miss/impact เพื่อ replay. บัฟ perfect dodge ถูกใช้เฉพาะ hit ตีปกติที่โดนจริงครั้งแรก; projectile พลาดไม่ใช้บัฟ. ไม่มี auto aim ของสกิลหรือการหักหลบติดตามเป้า.

## 4. ภาพอลังการภายใต้งบจริง
ตัวเลขเป็น **draw calls เพิ่มสูงสุดจาก VFX ของผู้เล่นในฉากเดียวกัน** ไม่รวมโมเดล/วงเตือน; ใช้ mesh รวมและ instance pool แชร์ระหว่างสกิล, ไม่มี texture หรือ post-process ใหม่บน Low/Medium. การเตรียมและจังหวะโดนต้องอ่านได้บน Low.
| ท่า | Low | Medium | High | สิ่งที่ Low ตัด |
|---|---:|---:|---:|---|
| ตีปกติแต่ละอาชีพ | +1 | +1 | +2 | ละอองและ trail รอง |
| S1 แต่ละอาชีพ | +1 | +1 | +2 | เศษเล็ก |
| S2 แต่ละอาชีพ | +1 | +2 | +3 | bloom ปลอม/ริบบิ้นรอง |
| S3 แต่ละอาชีพ | +1 | +2 | +3 | กลีบย่อยและแสงพื้นรอง |
| อัลติ (เมื่ออนุมัติเปิด) | +2 | +3 | +5 | เสารอง, แสงฟุ้ง |
**เพดานรวมทุก VFX ผู้เล่นพร้อมกัน:** Low +3, Medium +5, High +8 draw calls. หากชนเพดาน ให้ตัดละออง/trail ตกแต่งก่อน แต่คง silhouette ท่าและจังหวะ hit. High ก็ไม่ใช้แสงแดง/ส้ม ไม่มี flash เต็มจอ; bloom post-process ยังไม่เปิดโดยบรีฟนี้. ใช้สี+รูปทรง+เสียงแยกจากวงเตือน; VFX ไม่เขียนความหมายพื้นที่อันตราย. วัด `renderer.info` เมื่อซ้อน 3 สกิลและคำเตือนบอส รวมถึง fps/frame time มือถือจริง.

## 5. สมดุลและหน้าเลือกอาชีพ
เป้าทดลองบน seed เดียวกัน: เวลาไฟต์บอสทั้งสามอาชีพต่างกันไม่เกิน ±15% จาก Wayfarer โดยคนเล่นที่รู้ท่า; จำนวนครั้งที่โดนและจำนวนยาที่ใช้ใกล้กัน (รายงานแยก ห้ามปรับบอสตามอาชีพ). Replay ของ Wayfarer เดิมต้องเหมือนเดิมทุก tick. หากนักยิงไกลยืนยิงเฉย ๆ แล้วชนะโดยไม่หลบ/ล่อชนเสา ให้ปรับสกิลหรือมุมยิงก่อน ไม่เพิ่มระยะ/ความแรงบอสโดยพลการ.

หน้าเริ่มต้นคงปุ่ม “เริ่มเล่น” เข้า Wayfarer ทันที; เพิ่ม “เลือกอาชีพ” รองลงมา. หน้ารายชื่อ 3 ใบ: silhouette, ชื่อ, ระยะเล่น, ความยาก, ภาพตัวอย่างท่าเดียว และข้อความ “เล่นได้ทันที · ไม่บันทึกข้ามรอบ”. ปุ่ม “เริ่มด้วยอาชีพนี้” ส่ง `class` ใน run variant ที่ server whitelist และเก็บใน replay; ปุ่มย้อนกลับไม่เริ่มรอบ. หลังตาย/จบด่านเลือกใหม่ได้ก่อนรอบถัดไป; ระหว่างรอบห้ามเปลี่ยน. ลิงก์เก่าและ log เก่าที่ไม่มี class = Wayfarer. อาชีพที่ยังใช้ placeholder แสดง “ต้นแบบ” ไม่แสดงภาพ asset ที่ยังไม่รับ.

## 6. แนวจอและ HUD
**เลือกสลับอัตโนมัติตาม viewport**; ไม่เพิ่มปุ่มหมุน เพราะเว็บ iPhone บังคับการหมุนเครื่องไม่ได้. เมื่อ resize/orientation change ให้ reflow UI และปรับกล้องโดยไม่ restart sim/run, ไม่เปลี่ยนพิกัดอินพุตเกมหรือผล replay. คงแนวนอนเป็นเป้าหมายหลัก 844×390 ตามกฎเดิม; แนวตั้งเป็นโหมดทดลองที่เล่นได้. การ์ด “หมุนจอเพื่อมุมมองกว้างขึ้น” แสดงครั้งแรกเฉพาะ portrait พร้อม “เล่นแนวตั้งต่อ” และ “ไม่แสดงอีกในรอบนี้”; ห้ามบังศัตรูหลังเริ่มเดินหรือเริ่ม boss. ไม่เรียก orientation.lock บังคับแนวนอนเมื่อผู้เล่นเลือกแนวตั้ง; fullscreen/lock เป็น best effort เฉพาะเมื่อเข้า landscape และรองรับ.

**390×844 หลังหัก safe area**: พื้นที่เล่นชัดกลาง x=24–366, y=120–600. แถบบอสด้านบน y=42–84; คำแนะนำ y=88–115 (ยุบเมื่อสู้). จอยฐานศูนย์กลาง (72,735), เส้นผ่านศูนย์กลาง 106; โจมตี (337,758) Ø64; หลบ (269,758) Ø52; ยา (211,758) Ø48; สกิล 1/2/3 (338,680)/(278,680)/(218,680) Ø50; อัลติ (338,619) Ø48. ตัวเลขเป็น CSS px อ้างพื้นที่ 390×844; ยึดตำแหน่งตาม safe-area bottom/right/left, ไม่ให้ห่างขอบ <12 px และไม่ให้ hit target ทับกัน. Auto/ตั้งค่า (54,147)/(108,147) Ø44; หากชน hint ให้ย้าย hint เหนือ Auto หรือยุบ. กล้องแนวตั้ง FOV 62 เป็นค่าเริ่มทดลอง, ระยะ ×1.35 จาก landscape, ปรับตาม boss/telegraph ให้พัดระยะ 5.2 m เหลือขอบภาพด้านละ ≥0.4 m ณ tick เตือน; หากทำไม่ได้ ให้ถอยกล้อง/ลด FOV ตามที่เห็นวงครบโดยไม่เปลี่ยน hitbox. ไม่บังคับ x/y ของโลกตามตัวเลข CSS.

**จอแนวตั้งใหญ่**: ใช้ safe-area inset, ขยายพื้นที่ว่าง/ระยะห่างก่อนขยายปุ่ม; ปุ่มใช้งาน Ø48–72, จอย 106–124, ห้ามปุ่มทับ boss/วงเตือน. อย่า scale ทั้งหน้าตามความสูงอย่างเดียว. ที่จอแคบกว่า 390 หรือสูงน้อยกว่า 700 ต้องเก็บภาพและแจ้งข้อจำกัดก่อนประกาศรองรับ. ตรวจ touch target จริง iPhone/Android เพราะ CSS px ไม่ยืนยันความสบายของนิ้ว. ผังแนวนอนยึด DES-001 §3 เป็นเกณฑ์เทียบ; ขนาดที่ branch ปรับเล็กลง (ยา 40/อัลติ 43) ต้องวัดการกดจริงก่อนรับ.

## 7. บรีฟ asset สำหรับสร้างใบงานใน docs/handoff/
ทุกชุดเป็น **DRAFT** จนเจ้าของเห็นภาพในเกมและอนุมัติ. ทีม B แตกเป็นไฟล์ตาม TEMPLATE.md แยก `model_mage_v01`, `model_archer_v01`, `ui_classes_skills_v01`, `fx_classes_v01`; ลงที่มา prompt/เครื่องมือ/license/วันที่/รอบแก้ในใบงานและ ASSETS.md. ส่งเข้า `assets/_inbox/` แล้วตรวจสัญญา asset ก่อนใช้. ห้ามคัดลอกทรง/ไอคอนจากเกมอื่น.

- **Mage model:** low-poly cel shade 1.5 m, หัว ~40%, ไม้เท้าหยดผลึก, ผ้าคลุมสองชาย, วงข้อมือ; palette lumen/violet/gold. body/head/staff แยก node และ pivot ด้าม, หัน +Z; ไม่เพิ่ม rig หาก pipeline เดิมยังขยับชิ้น. ตรวจ silhouette ที่ 44–60 px และมุมกล้องจริง, ด้านหลัง, ท่าหลบ, ไม่บังวงเตือน.
- **Archer model:** 1.5 m, หัว ~40%, คันธนูปีกไม่สมมาตร, ซองลูกศรเฉียง, teal/blossom; body/head/bow แยก node กับ pivot มือ, +Z; ตรวจระยะปล่อย projectile ตรงหัวธนูและไม่บังจอย.
- **Icons:** PNG RGBA โปร่ง 128×128 ต่อท่า, 4 ท่าต่ออาชีพ (อัลติแสดงล็อก) และ portrait/ใบเลือกอาชีพแยกตามการอนุมัติ; ไม่มีข้อความ/ฉากหลัง, รูปทรงตามตาราง, อ่านได้ที่ 48–54 CSS px ทั้งพร้อมใช้และ cooldown. ห้ามนำภาพที่สร้างมาอ้างเป็นผลในเกมก่อน render จริง.
- **VFX:** ระยะแรกใช้ geometry/instance pool ใน Three.js ไม่มี texture จำเป็น; หากต้องใช้ texture ให้บรีฟแยก RGBA ไม่เกิน 256²/ไฟล์ พร้อม provenance และวัดงบใหม่; sound ใช้ synthesized event ตาม tick, ทำโทนแก้ว/สายธนู ไม่กลบเสียงเตือน. ตรวจสีห้ามชนวงเตือน.
- จำกัด GLB รวมตาม contract เดิม ≤1.2 MB/60k tris (เป้า 700 KB หากทำได้); ส่ง tri/bytes ก่อน–หลังและผล verify_kit. โมเดลใหม่ต้องมีภาพเก่า/ใหม่ในเกมบนพื้นและหมอกจริง, ไม่ใช้แค่ render พื้นเทา.

## 8. ลำดับผลิตและเกณฑ์รับ
1. ทีม B เพิ่ม class run variant/server whitelist/replay โดย Wayfarer เดิมต้อง replay เท่าเดิม. ทำ orientation reflow จาก layout เดิมก่อน แล้วส่งภาพ 390×844/844×390 และ touch test; ไม่รอ asset.
2. ทำ Mage แบบ placeholder: projectile swept collision, การล็อกทิศ, S1–S3; test tick hit/cooldown/cancel/dodge, เสา/ผนัง, ID tie, จำนวน hit ต่อเป้า, replay/server. ส่งคลิป boss/ศัตรูและค่า damage. ตรวจจุดยิงไกลล่อบอสชนเสา.
3. ทำ Archer ด้วย primitive เดียวกัน, test 3 ศรโดนเป้าเดียวไม่คูณ, เจาะและชนเสา, พื้นที่ค้าง, replay. ส่งภาพสกิลก่อน/โดน/จบ, VFX ซ้อน telegraph ทั้ง Low/Medium/High และ draw calls ก่อน–หลัง.
4. หน้าเลือกอาชีพ, ตรวจ URL เก่า/จบรอบ/ตาย/เปลี่ยนอาชีพ/refresh; ภาพเทียบ UI แนวนอนและแนวตั้ง. ทำใบงาน asset ทีละชิ้น เสนอเจ้าของพร้อมภาพในเกมก่อนเข้า build หลัก.
5. เพลย์เทสต์คนจริงบน iPhone และ Android ทั้งสองแนว: FPS/frame time ระหว่าง boss + 3 VFX, การกดแต่ละปุ่ม, boss/วงเตือน/ขอบพัด, เวลาจบและจำนวนครั้งโดนเทียบ seed เดียวกับ Wayfarer. ส่งผลให้ทีม A จูนก่อนเปิดอัลติ. ไม่อ้าง headless ว่าผ่านมือถือจริง.
