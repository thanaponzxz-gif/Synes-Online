## 1. ความต้องการของเจ้าของ (ยกมาตรง ๆ 2026-11-21)

นี่คือคำตอบ **Q50** ของ REQ-004 ด้วย: คำว่า "เพื่อใช้โทเคน" หมายถึง **สกิลใช้มานา** ไม่ใช่โควตา AI
**สมมติฐานใน DES-005 บรรทัดท้ายจึงไม่ถูก** ทีม B จะพัก tuning สกิลของนักเวท/นักธนูตามที่ DES-005 สั่งไว้ จนกว่าจะได้ระบบมานา

ทีม B แยกได้ 4 เรื่อง
| เรื่อง | ความหมายที่ทีม B เข้าใจ | ยืนยันแล้ว? |
|---|---|---|
| ก. มานา | สกิลทุกช่องต้องใช้มานา ("สกิลในเกม" ทีม B เข้าใจว่ารวมทุกอาชีพ) | ยังไม่ยืนยันว่ารวมนักเดินทางและโจมตีปกติหรือไม่ (Q62) |

### 1.1 ฟังก์ชันของระบบอ้างอิง ตามที่ทีม B เข้าใจ (ใช้เป็นเรฟฟังก์ชันเท่านั้น ให้เจ้าของยืนยัน)
"Ro" ทีม B เข้าใจว่าคือเกม Ragnarok Online แต่ใช้ได้เฉพาะ **วิธีการทำงาน** ชื่อการ์ด ไอเทม มอนสเตอร์ ภาพ และตัวเลขต้องเป็นต้นฉบับทั้งหมด (PROJECT_SYNES ข้อ 1)
| ฟังก์ชัน | ทีม B เข้าใจว่า |
|---|---|
| ตารางดรอป | มอนสเตอร์แต่ละชนิดมีรายการไอเทมหลายชิ้น แต่ละชิ้นมีโอกาสดรอปคงที่ต่อการฆ่าหนึ่งครั้ง |
| ประเภทไอเทม | ยาฟื้นพลัง (HP/มานา), วัตถุดิบ, อุปกรณ์สวมใส่ และการ์ด |
| การ์ดมอนสเตอร์ | มอนสเตอร์แต่ละชนิดมีการ์ดประจำตัว 1 ใบ ดรอปยากมาก |
| ช่องเสียบการ์ด | อุปกรณ์มีช่อง 0 ถึงหลายช่อง เสียบการ์ดแล้วได้ผลติดตัว (เพิ่มค่าสถานะ, เพิ่มดาเมจต่อศัตรูบางประเภท, ผลพิเศษเมื่อตี/โดนตี) |
| ข้อจำกัดการเสียบ | การ์ดแต่ละใบใส่ได้เฉพาะอุปกรณ์บางประเภท (อาวุธ เกราะ ฯลฯ) และเสียบแล้วถอดไม่ได้ |
| มานา | คล้ายค่า SP: ใช้ร่ายสกิล ฟื้นเองตามเวลา และมียาฟื้น |

## 2. ข้อเท็จจริงใน repo ตอนนี้
- **มานา:** ไม่มีเลย สกิลทุกช่องใช้แค่คูลดาวน์ (DES-001 นักเดินทาง 3 สกิล + DES-005 นักเวท/นักธนู ที่ยังไม่ได้ทำ)
  HUD มีแถบ HP ผู้เล่นและบอส (skin DES-002) แต่ไม่มีแถบมานา
- **รางวัลตอนนี้** (`shared/rules/reward.ts`): ได้ตอนชนะบอสเท่านั้น
  - ได้ทอง + EXP + ไอเทม 1 ชิ้นจาก 3 ชิ้น: เศษน้ำค้างแสง (common 70), เศษเขาปริซึม (uncommon 25), ใบระฆัง: จูนรุ่งอรุณ (rare 5 ×3 ถ้าได้อันดับ S)
  - server เป็นคนสุ่ม (HMAC ของ runId กับรหัสลับของ server) client จึงทายผลล่วงหน้าไม่ได้
  - มอนสเตอร์ทั่วไปไม่ดรอปอะไร
- **ไอเทม ทอง และ EXP ที่ได้ ไม่ถูกเก็บไว้ที่ไหนเลย** แสดงบนหน้าผลจบแล้วหายไป
  ไม่มีกระเป๋า ไม่มีอุปกรณ์สวมใส่ ไม่มีเลเวล ไม่มีบัญชี และไม่มีฐานข้อมูล
  server เก็บข้อมูลรอบไว้ในหน่วยความจำและหายเมื่อรีสตาร์ต
- **GitHub Pages ที่เจ้าของใช้เล่นบน iPhone เป็นโหมดออฟไลน์ (ไม่มี server)** หน้าผลจบขึ้นว่า "รอบนี้ไม่ถูกบันทึกและไม่ได้รับรางวัล"
- **มอนสเตอร์มีแค่ 3 ชนิด:** พัฟแคป (HP 40), ธอร์นลิง (HP 55) และบอสปริซึมแบ็ก (HP 1000) ในด่านเดียวคือทุ่งน้ำค้างแสง
- input เก็บปุ่มได้ 8 บิตและใช้ครบแล้ว ปุ่มบนจอมี 7 ปุ่ม + Auto/ตั้งค่า Auto (DES-001)
- ระบบโจมตีอัตโนมัติ (DES-001 §4) กำลังทำอยู่ในเซสชัน MAIN ระบบนี้ใช้สกิลเองตามที่ผู้เล่นตั้งไว้ มานาจึงกระทบพฤติกรรมของ Auto ด้วย

## 3. ข้อจำกัดทางเทคนิคและกฎที่ล็อกไว้
**3.1 ผลต่อสู้และรางวัล (ADR-002)**
- ทุกอย่างที่มีผลต่อการต่อสู้ (มานา, ค่าใช้มานา, การฟื้น, ผลของการ์ด, ค่าของอุปกรณ์) ต้องคำนวณใน sim แบบ deterministic 30 Hz
  ขอตัวเลขในรูปที่ใส่ `tuning.ts` ได้ (tick, เมตร, จำนวนเต็มถ้าเป็นไปได้) ห้ามใช้ trig และห้ามสุ่มแบบ `Math.random`
- **client ห้ามตัดสินรางวัล** ดรอปต้องสุ่มโดย server
  - ตอนนี้ client รู้ seed ของรอบ ถ้าให้ sim สุ่มดรอปจาก seed นั้น client จะทายดรอปได้ล่วงหน้า
  - ถ้าต้องการให้ไอเทมตกบนพื้นทันทีที่ฆ่ามอนสเตอร์ ทีม B ต้องทำกลไกเพิ่ม (ใช้รหัสลับของ server แล้วเปิดผลตอนจบรอบ หรือมี server แบบเวลาจริง) ซึ่งทีม B ทำได้
    แต่ต้องรู้ก่อนว่าผู้เล่นต้อง **เห็นดรอประหว่างเล่น** หรือ **เห็นตอนจบรอบ** (Q64)
- ถ้าการ์ด/อุปกรณ์มีผลกับการต่อสู้ server ต้องรู้ว่าผู้เล่นใส่อะไรเข้ารอบ และต้องตรวจว่าผู้เล่นมีของนั้นจริง ซึ่งต้องมีการเก็บกระเป๋าไว้ที่ server

**3.2 การเก็บของข้ามรอบ (ต้องให้เจ้าของตัดสิน)**
- ไอเทมและการ์ดจะมีความหมายก็ต่อเมื่อเก็บไว้ข้ามรอบได้ ซึ่งต้องมีบัญชีผู้เล่น (อย่างน้อยเป็น guest id), ฐานข้อมูล และโฮสต์ที่มี server
  **ต้องใช้บริการภายนอก/อาจมีค่าใช้จ่าย จึงต้องให้เจ้าของอนุมัติ** (CLAUDE.md ข้อ 6) และตรงกับ backlog ข้อ 7
- เก็บในเครื่องผู้เล่น (localStorage) ทำได้ทันทีและเล่นบน Pages ได้ แต่ผู้เล่นแก้ค่าเองได้ จึงขัด ADR-002 ถ้าเป็นของที่มีผลต่อการต่อสู้หรือรางวัล
- กฎโปรเจค: "ทำ vertical slice ให้เล่นสนุกก่อน **ห้ามสร้างระบบ MMORPG ทั้งหมดล่วงหน้า**" ขอให้ทีม A กำหนดขอบเขตรุ่นแรกที่เล็กที่สุดที่ยังทดสอบความสนุกของระบบได้
- เกมต้องกดลิงก์แล้วเล่นได้ทันทีโดยไม่สมัครบัญชีก่อน (PROJECT_SYNES ข้อ 1)

**3.3 ภาพ UI และ asset**
- ต้องมีหน้าจอใหม่หลายหน้า (กระเป๋า อุปกรณ์ เสียบการ์ด) บนจอมือถือแนวนอน 844×390 และแนวตั้ง 390×844 (DES-005 §6)
- ไอคอนไอเทมและภาพการ์ดเป็น asset ต้องมีบรีฟใน `docs/handoff/` และเจ้าของต้องอนุมัติ (ADR-006) ระหว่างรอ ทีม B ใช้ placeholder
- สีส้ม #FF7A1A และแดง #FF3355 สงวนไว้ให้วงเตือน ไอเทมหรือการ์ดระดับหายากใช้สีนี้ไม่ได้
  (หน้าผลจบตอนนี้ใช้คลาส CSS `common/uncommon/rare` แสดงความหายาก)
- ห้ามคัดลอกชื่อ ภาพ หรือรายการการ์ด/ไอเทมของ Ro หรือเกมอื่น

**3.4 มานา**
- ถ้าต้องมียาฟื้นมานาเป็นปุ่มแยก ต้องขยายรูปแบบ input (ทีม B ทำได้) และต้องมีที่วางปุ่มเพิ่มในผังทั้งสองแนว
- มานาเปลี่ยนสมดุลสกิลของนักเดินทาง (DES-001) ที่เล่นอยู่แล้วบน Pages และกระทบ Auto (DES-001 §4) ด้วย
- ถ้าเปลี่ยนกติกา input log เก่าจะเล่นซ้ำได้ผลต่างจากเดิม ต้องกำหนดเวอร์ชันกติกา (ทีม B ทำส่วนเทคนิค)

## 4. สิ่งที่ทีม B ต้องได้กลับ (ใน `DES-006-...md`)
1. **ระบบมานา:** มานาสูงสุดของแต่ละอาชีพ, ค่าใช้ของทุกสกิล (นักเดินทาง + นักเวท + นักธนู), การฟื้น (ต่อ tick / เมื่อตี / ยา), ความสัมพันธ์กับคูลดาวน์, มานาไม่พอแล้วกดสกิลจะเกิดอะไร, แถบมานาบน HUD ทั้งสองแนว และผลต่อ Auto
   ถ้าต้องปรับคูลดาวน์หรือดาเมจใน DES-001/DES-005 ให้ระบุตัวเลขใหม่
2. **ไอเทม:** ประเภท, รายการไอเทมของมอนสเตอร์แต่ละชนิด (รวมบอส) พร้อมชื่อไทย/อังกฤษ ความหายาก และโอกาสดรอป, ไอเทมแต่ละชิ้นใช้ทำอะไร และดรอปปรากฏตอนไหน
3. **การ์ด:** การ์ดของมอนสเตอร์แต่ละชนิด, ผลเป็นตัวเลขที่ sim คำนวณได้, ใส่ได้กับอุปกรณ์ประเภทไหน, โอกาสดรอป, กฎการเสียบ/ถอด และเพดานไม่ให้การ์ดซ้อนกันจนบอสง่ายเกิน
4. **อุปกรณ์** (ถ้าการ์ดต้องเสียบในอุปกรณ์): ช่องสวมใส่, จำนวนช่องการ์ด และค่าของอุปกรณ์ เพราะตอนนี้เกมยังไม่มีอุปกรณ์เลย
5. **ระบบอื่นของ Ro ที่จะใช้** ตามคำตอบ Q60 พร้อมขอบเขตรุ่นแรก
6. **หน้าจอ:** กระเป๋า อุปกรณ์ เสียบการ์ด และหน้าผลจบที่แสดงดรอป ทั้งแนวนอนและแนวตั้ง
7. **ลำดับงานและขอบเขตรุ่นแรก** (อะไรทำได้ก่อนมีบัญชี/ฐานข้อมูล และอะไรต้องรอ) พร้อมเกณฑ์ตรวจรับ
8. **บรีฟ asset** ตาม `docs/handoff/TEMPLATE.md`: ไอคอนไอเทม ภาพการ์ด แถบมานา และไอคอนยามานา (ถ้ามี)
