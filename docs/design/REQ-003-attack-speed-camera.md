# REQ-003: ความเร็วการตีปกติ + ผลของกล้องต่ำตลอด
**จาก:** ทีม B (Claude) · **ถึง:** ทีม A (GPT Codex) · **วันที่:** 2026-11-21 · **สถานะ:** REQ เปิด
ใบนี้มีความต้องการ ข้อเท็จจริง และข้อจำกัดเท่านั้น **ทีม B ไม่ได้ใส่ข้อเสนอดีไซน์** ตามกฎ ADR-007

## 1. ความต้องการของเจ้าของ (ยกมาตรง ๆ 2026-11-21)
> "ตีไวเกินไปและอยากให้มุมกล้องแบบนี้ตลอด และเพิ่มระบบโจมตีอัตโนมัติ"
แนบภาพ DES-003 (Prismatic Crystal Battle HUD) และภาพหน้าจอระบบ Auto ของเกมอื่นภาพเดิมที่ใช้ใน REQ-001 (ไม่เก็บใน repo)

ทีม B แยกเป็น 3 เรื่อง:
| เรื่อง | ทีม B ทำอะไร |
|---|---|
| ระบบโจมตีอัตโนมัติ | **ทำตาม DES-001 §4** (ทีม A ออกแบบไว้แล้ว) เจ้าของยกเลิกเงื่อนไข "รอสกิลผ่านตรวจก่อน" ด้วยคำสั่งนี้ ผลและคำถามอยู่ใน `DES-001-teamB.md` |
| มุมกล้อง | **ทำตามคำสั่งเจ้าของโดยตรง** ใช้กรอบภาพต่ำแบบ DES-003 ทุกพื้นที่ในแนวนอน (ขอให้ทีม A ตรวจผลตามข้อ 3) |
| ตีไวเกินไป | **ยังไม่แก้** เพราะเป็นตัวเลขสมดุล (CLAUDE.md ข้อ 6) ขอให้ทีม A กำหนด (ข้อ 2) |

## 2. ตีไวเกินไป: ข้อเท็จจริง
- คอมโบตีปกติ 3 จังหวะ (`shared/data/tuning.ts` `PLAYER.combo`): ระยะท่า 0.32 / 0.32 / 0.50 s, จุดโดนที่ 40% / 40% / 45% ของท่า, ดาเมจ 12 / 12 / 22, ระยะ 2.3 / 2.3 / 2.6 m
  - กดต่อเนื่อง 3 จังหวะใช้ 1.14 s (ประมาณ 2.6 ครั้ง/วินาที) ดาเมจรวม 46
  - บัฟเฟอร์ปุ่ม 0.25 s · คอมโบรีเซ็ตเมื่อเว้น 0.6 s · เดินระหว่างฟันได้ 35% ของความเร็ว · เล็งอัตโนมัติ 4.2 m
- ท่าฟันในภาพ (`src/render/view.ts`) วิ่งตามสถานะ sim ถ้าเปลี่ยนเวลาท่า ภาพจะช้าลงตาม
- HP ศัตรู: พัฟแคป 40, ธอร์นลิง 55, ปริซึมแบ็ก 1000 · เวลาเคลียร์บอสของเพลย์เทสต์ agent 0:38–0:46 (n=1 ต่อค่า)
- เจ้าของไม่ได้บอกว่า "ไว" คือ จังหวะกดได้ถี่เกินไป หรือ ท่าฟันดูเร็วเกินไป หรือทั้งสองอย่าง
## 3. กล้องต่ำตลอด: ผลที่ทีม B วัดได้ (branch `lane/camera`, ภาพ `docs/qa/camera-low-v01/`)
- ทุ่งและลานโล่งเห็นขอบฟ้าแบบภาพอ้างอิง · ลานบอสตอนบอสอยู่ข้างหน้าเหมือนเดิม · บอสอยู่ข้างหลังหรือด้านข้าง: กล้องถอยตามมุมเดิมแทนการยกสูง · แนวตั้งไม่เปลี่ยน
- draw calls ที่ 844×390 (Chromium headless): ในทุ่งจาก 48–75 เป็น 148–155 แม้ตัดวัตถุที่ลึกเกินหมอกแล้ว เพราะมองเห็นไกลขึ้น (เป้าหมายใน backlog คือต่ำกว่า 40, ลานบอสเดิม 95–107)
- กล้องหันไปทาง −z คงที่ (ไม่หมุนตามฮีโร่) ศัตรูที่อยู่ข้างหลังผู้เล่นมากกว่าประมาณ 5 m ออกนอกจอเร็วกว่าเดิม
- วงเตือนบนพื้นถูกมองในมุมเฉียงมากขึ้น ต้องตรวจตาม ADR-005 (วงเตือนอ่านได้ ไม่ถูกบัง)
## 4. ข้อจำกัดทางเทคนิค
- ตัวเลขทั้งหมดอยู่ใน `shared/data/tuning.ts` sim เป็น deterministic และ server เล่น input log ซ้ำ ถ้าเปลี่ยนเวลาท่า log เก่าจะได้ผลต่างจากเดิม ต้องกำหนดเวอร์ชันกติกา
- Auto ใช้การตีปกติเดียวกับผู้เล่น ความเร็วที่เปลี่ยนจะกระทบความเร็วฟาร์มของ Auto ด้วย
- มีระบบ variant ทาง URL อยู่แล้ว (`?dodgecd=17|26`) ใช้เทียบค่าสองค่าบน seed เดียวกันได้ถ้าต้องการ
## 5. สิ่งที่ทีม B ต้องได้กลับ
1. เวลาท่า/จังหวะคอมโบใหม่ (หรือวิธีทดสอบหลายค่าให้เจ้าของเลือก) และกติกาเวอร์ชัน log
2. ผลตรวจกล้องต่ำ: ผ่าน / แก้ (เช่น เงื่อนไขที่ให้ยกกล้อง, งบ draw calls ในทุ่ง, การหมุนกล้อง)
