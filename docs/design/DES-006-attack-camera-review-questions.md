**เวอร์ชัน log:** แยก `inputFormatVersion` (v1/v2 Auto) จาก `rulesetVersion`. Log ใหม่บันทึก `rulesetVersion: combo-A|combo-B|combo-C` (เมื่อเลือกค่าใช้จริงให้ชื่อถาวร เช่น `combat-2`), seed, class, variants และ hash ของ tuning. Replay/verify ต้องเลือกกติกาเดิมตาม log; log เดิมไม่มี field = `combat-1` และใช้ combo เก่าทุกค่า. Server ปฏิเสธ ruleset ที่ไม่รู้จัก; ห้ามนำ log เก่ามาจำลองด้วย combo ใหม่แล้วอ้างว่าผลตรง. ทดสอบ fixture เดิม byte/result เดิม และ cross-version ที่ต่างโดยตั้งใจ. หาก log format v1/v2 ถูก encode ใน tuple โดยไม่มี metadata ให้ version นี้อยู่ใน run envelope ที่ server ตรวจและบันทึก ไม่แอบยัดลงปุ่ม 8 บิต.

**กล้องต่ำตลอด: แก้ก่อนรับ.** มุมต่ำเป็นเป้าภาพ แต่ในทุ่ง 48–75 → 148–155 draw calls (headless) สูงเกินไป. กำหนดงบทุ่งชั่วคราว Low ≤80, Medium ≤100 draw calls ในช็อตมุมต่ำ 844×390 (เทียบฉากเดิมและบันทึกข้อแตกต่าง); เป้าระยะยาว <40 ไม่ใช่ gate ของงานนี้. ใช้ culling/LOD/instancing/ลดวัตถุไกลตามลำดับโดยไม่ทำให้ภาพที่เจ้าของชอบหาย. เมื่อศัตรูหรือขอบวงเตือนหลุดจอ ให้กล้องถอย/ยกขึ้นชั่วคราวอย่างนุ่มนวลจนเห็นการเตือนครบ แล้วกลับมุมต่ำ; ไม่หมุนกล้องตามผู้เล่นโดยอัตโนมัติในรอบนี้เพราะเปลี่ยนทิศควบคุม. ทดสอบ boss อยู่หน้า/หลัง/ข้าง, มอนห่างหลัง >5 m, เสาและวงทุกท่า, portrait แยก, พร้อม FPS/frame time iPhone/Android จริง. ห้ามรับกล้องต่ำคงที่หากวงเตือนถูกตัดหรือมอนตีจากนอกจอโดยไม่เห็น.

## 2. DES-003: ผังปุ่มและวงเตือน
พิกัด DES-001 §3 เป็น baseline ไม่ใช่ข้อยกเว้นให้ลด touch target. ชุดปุ่มกลางทางโจมตี 76 ผ่านเชิงขนาด; หลบ 48, สกิล 49 พอทดลอง (ต้องมี hit target ≥44); ยา 40 และอัลติ 43 **ไม่ผ่าน** ให้แก้เป็นอย่างน้อย 44 px และพื้นที่กดจริงไม่ชนกัน. คำสั่งเจ้าของใหม่ skill-row-v01 ให้ใช้แถวล่างตาม Q69–73: 50 px สกิล, 46 อัลติ, 52 หลบ, 44 ยา. ตรวจ safe area, ซ้าย/ขวานิ้วจริง และความทึบเมื่อทับวงเตือนใน 844×390; ภาพอ้างอิงเป็นเพียงตำแหน่ง ไม่คัดลอก asset.

**วงเตือน: ต้องแก้.** Edge headless รายงานพิกเซลส้ม/แดงสดท่าพุ่ง 64→0 หลังบรรยากาศ; ภาพ “ยังอ่านได้” ไม่พอผ่านเกณฑ์ DES-004 §6 และ ADR-005. ให้แยกสีเตือนจาก fog/lighting/material ด้วย pass หรือ shader ที่คงสีส้ม/แดงและวาดเหนือ VFX; คง hitbox, เวลาเตือน, ความโปร่งในวง, ขอบบางเดิม. เทียบเฟรมเดียวกันก่อน/หลังสำหรับ slam/sweep/charge ทั้ง 844×390 และจอใหญ่, มอง grayscale/สีจริง, ตรวจไม่บังหน้าบอสและชัดเหนือพื้น/ผลึกทุก tier. วัดสีเฉพาะ ROI ขอบวง ไม่ใช้จำนวนพิกเซลทั้งจอเป็นเกณฑ์เดียว. ส่งคลิปมือถือก่อนรับจริง.

## 3. DES-004 §8: รับแบบมีเงื่อนไข
**รับทิศทางศิลป์และแผนขั้น 2–6 ให้ทำเป็นต้นแบบแยกทีละขั้น**; ขั้น 1 ยังไม่ผ่านตรวจรับสุดท้าย เพราะผลึกซ้าย luma 0.31 ต่ำกว่าพื้น 0.34, วงเตือนสีอุ่นลด, ชื่อบอส 13 px ต่ำกว่าเกณฑ์ 14 px. แก้แสง/วัสดุผลึกซ้ายให้สว่างกว่าพื้นในช็อตเปิดโดยไม่ทำให้วงเตือนจมหาย; ชื่อบอส ≥14 CSS px ที่ 844 พร้อมวัดไม่ชน HUD. ตรวจลำดับ visual hierarchy ที่กล้องต่ำใหม่ด้วย. งบ +1/+2/+3 calls ขั้น 1 อยู่ในกรอบเดิม แต่ยังไม่มีผล FPS เครื่องจริง. ขั้น 2–4 ต้องมีภาพจากเกมจริงทั้งก่อน/หลังและตรวจ `verify_kit.py`/ขนาด GLB; ขั้น 5–6 ผ่าน asset pipeline และเจ้าของรับภาพก่อนใช้จริง. ใช้ Opus ตามคำสั่งเจ้าของสำหรับงานกราฟิก. DES-003/004 เป็นงานทีม A ที่เจ้าของชี้แจงแล้ว ไม่ลงรายการข้อยกเว้น ADR-007; แก้ข้อความสถานะเก่าของ DES-004 ที่กล่าวว่าเป็นข้อยกเว้นให้ตรงกับมตินี้. ผ้า teal ต้องยังอ่านเป็น “ผ้าพันคอ” จากมุมเล่นจริง; ถ้ามีเฉพาะปลอกคอเล็ก ให้เพิ่มส่วน teal ที่มองเห็น ไม่เปลี่ยนหางผ้าม่วง/เงินโดยไม่ส่งภาพให้เจ้าของเทียบ.
