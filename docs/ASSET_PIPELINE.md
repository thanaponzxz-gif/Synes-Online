# Hybrid Asset Pipeline v1: ฉบับใช้กับ Synes

> กฎกลางจากเจ้าของ (2026-11-20) ใช้ร่วมทุกโปรเจกต์เกม ไฟล์นี้แปลงกฎให้ตรงกับ Synes
> ข้อที่ขัดกับการตัดสินใจเดิม เจ้าของตัดสินแล้วในหัวข้อ "มติเจ้าของ" ด้านล่าง
> **กฎเหล็ก ADR-007 (2026-11-20):** งานออกแบบทุกประเภทให้ GPT Codex (ทีม A) ออกแบบหรือเขียนบรีฟก่อน แล้ว Claude (ทีม B) จึงลงมือทำ ดู CLAUDE.md ข้อ 0 และ `docs/design/README.md`

## 1. บทบาท
| บทบาท | ใน Synes |
|---|---|
| เจ้าของโปรเจกต์ | กำหนดวิสัยทัศน์และอนุมัติ asset ทุกชิ้นก่อนใช้จริง (เปลี่ยนสถานะเป็น APPROVED) |
| Claude (PM, **ทีม B**) | วางแผน แบ่งงาน เขียนใบขอออกแบบ (`docs/design/REQ-*`) นำงานเข้า repo ทดสอบ และส่งผลกลับให้ทีม A ตรวจ **ไม่ออกแบบและไม่เขียน Art Brief เอง** (ADR-007) |
| GPT Codex (**ทีม A**) / GPT Image | **ทีม A ออกแบบหรือเขียนบรีฟทุกงานก่อน** (ระบบเกม, สกิล/VFX, UI/UX, ตัวละคร, มอนสเตอร์, ฉาก, asset) แล้วตรวจผลที่ทีม B ส่งกลับ ส่วน GPT Image ผลิตภาพตามบรีฟ เจ้าของเป็นคนส่งต่อระหว่างทีมและนำไฟล์มาไว้ใน `assets/_inbox/` |
| Blender | โมเดล 3D/rig/animation ตามมาตรฐานด้านล่าง (ผลิตด้วย `tools/blender/build_kit.py` ตามมติ ข-2) |
| ประกอบเกม / build | **Synes ใช้ Three.js + Vite ตาม ADR-001 ไม่ใช่ Godot** (มติ ข-1) |
| QA | agent `synes-playtest` + เจ้าของเล่นจริงก่อนอนุมัติ |

## 2. งานศิลป์
- Claude ไม่สร้างภาพหรืองานศิลป์สำเร็จรูปเอง ไม่แก้ภาพวนซ้ำ และไม่เขียน brief เอง ทีม A (Codex) เขียน brief ส่วน Claude นำเข้าเกม ทดสอบ แล้วส่งผลกลับให้ทีม A ตรวจ (ADR-007)
- ภาพจาก GPT เป็นต้นแบบหรือทิศทาง ยังไม่ใช่ asset สุดท้าย เว้นแต่เป็น UI/ไอคอน/texture ที่ผ่านการตรวจแล้ว
- Synes เป็นเกม 3D ดังนั้นตัวละคร ศัตรู และพร็อพต้องเป็นโมเดล .glb ส่วน PNG ใช้ได้กับ UI, ไอคอน, texture, concept และฉากหลังไกลเท่านั้น
- ระหว่างรอ asset จริงใช้ **placeholder** ได้ (รูปทรงพื้นฐาน, SVG/CSS ในโค้ด) และต้องลงทะเบียนใน `docs/ASSETS.md` ว่าเป็น placeholder

## 3. ไฟล์กลาง
- `docs/handoff/<asset>.md` = ใบสั่งงาน 1 ใบต่อ 1 asset ใช้ `docs/handoff/TEMPLATE.md`
  สถานะ: **DRAFT** (Claude กำลังเขียน) → **REVIEW** (มีไฟล์ใน inbox รอตรวจ) → **APPROVED** / **REJECTED** (เจ้าของตัดสิน)
- `assets/_inbox/` = ไฟล์ที่ GPT, Tripo หรือ Blender ส่งกลับมารอตรวจ **ห้ามโค้ดเกมอ้างถึงไฟล์ในนี้**
- งานที่ APPROVED แล้วย้ายเข้า `public/assets/` (โฟลเดอร์ที่เกมโหลดจริง) ตามประเภท: `models/`, `ui/`, `textures/`
  แล้วลงทะเบียนใน `docs/ASSETS.md` พร้อมที่มา

## 4. มาตรฐาน asset
- ชื่อไฟล์ `ประเภท_ชื่อ_vNN` เช่น `char_wayfarer_v01.glb`, `ui_potion_v01.png`, `tex_sand_v01.png`
  ประเภท: `char` ตัวละคร · `enemy` ศัตรู · `prop` พร็อพ · `env` ฉาก · `ui` UI/ไอคอน · `tex` texture · `concept` ภาพแนวคิด · `fx` เอฟเฟกต์
- 3D ส่งออกเป็น .glb และภาพเป็น .png (โปร่งใสถ้าเป็น UI/ไอคอน)
- ทุก asset ต้องบันทึกที่มา ได้แก่ เครื่องมือ, prompt ฉบับเต็ม, license หรือเงื่อนไขการใช้งาน และวันที่ ในใบสั่งงานและใน `docs/ASSETS.md`
- ห้ามลอกตัวละครหรืองานที่มีลิขสิทธิ์ ใช้ reference ได้เพื่อดัดแปลงเป็นสไตล์ของ Synes เท่านั้น
- กฎเฉพาะ Synes: สีส้ม #FF7A1A และแดง #FF3355 ใช้กับวงเตือนเท่านั้น ห้ามใช้ใน asset อื่น

## 5. เครื่องมือและโควตา
- container คลาวด์ของ Claude **ไม่มี GPU** (ตรวจแล้ว 2026-11-20: ไม่มี `nvidia-smi`, 4 CPU, RAM 15 GB) Blender จึงเรนเดอร์ด้วย CPU
  ถ้าจะใช้ GPU บนเครื่องเจ้าของ ต้องตรวจสเปกก่อน (ยังไม่ทราบ)
- บริการที่ต้องสมัครหรือเสียเงิน (เช่น Tripo) ต้องขออนุมัติก่อนทุกครั้ง
- ห้ามติดตั้งสิ่งใด ลบไฟล์ หรือเปลี่ยนการตั้งค่าระบบโดยไม่ได้รับอนุญาต ส่วนการ push ไป repo ของ Synes ได้รับอนุญาตแล้วใน CLAUDE.md ข้อ 6 (มติ ข-3)

## 6. โมเดล AI ที่ใช้ในแต่ละงาน
- **Opus:** วางแผน เขียนใบขอออกแบบ ตรวจผล และตัดสินใจเรื่องเทคนิค (ตัวดีไซน์เป็นของทีม A ตาม ADR-007)
- **Sonnet:** เขียนโค้ด นำ asset เข้าเกม และงานที่ทำซ้ำ (subagent ใช้ `model: sonnet`)
- **Fable:** ใช้เฉพาะปัญหาสถาปัตยกรรมที่ยากจริง
- ทุกครั้งที่ส่งงานต้องระบุว่า **ขั้นถัดไปควรใช้โมเดลไหน**

## 7. นำร่อง

## มติเจ้าของ (2026-11-20) สำหรับ 3 ข้อที่ขัดกับการตัดสินใจเดิม
- **ข-1 เอนจิน:** อนุมัติให้ Synes ใช้ Three.js ต่อตาม ADR-001 ในกฎนี้ Three.js + Vite ทำหน้าที่ประกอบเกมแทน Godot
- **ข-2 โมเดลจากสคริปต์ Blender:** นับเป็นงานบทบาท "Blender"
  - โมเดลใหม่ทุกชิ้นต้องมีใบสั่งงาน และ**ส่งภาพเทียบในเกมให้เจ้าของอนุมัติก่อนนำเข้า build หลัก**
  - ชุดเดิม (`synes_kit.glb`) ใช้เป็น placeholder ได้
- **ข-3 การ push:** คงสิทธิ์ตาม CLAUDE.md ข้อ 6 สำหรับ repo ของ Synes
  - การเปิด Share สาธารณะและการตั้งโฮสต์ต้องรอเจ้าของอนุมัติแยกทุกครั้ง
  - push ไป remote ใหม่ต้องถามก่อนเหมือนเดิม
